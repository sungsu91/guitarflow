# PDF TAB 복합박자·반복 스트럼 검증 (2026-09-30)

## 원인과 변경

여수밤바다 원본은 12/8이다. 기존 인식기는 프렛과 대부분의 기둥·꼬리를 읽었지만, 마디 검증과 제작실 변환에서 4/4의 1,920 tick을 고정 사용했다. 실제 12/8의 2,880 tick을 넘는 것으로 처리해 리듬을 대체했고, 미확정 이벤트의 반복 운지 생략도 표시되지 않았다.

- `printedMeter.js`: TAB 시작부의 큰 위·아래 숫자 두 개를 분리해 기존 다중 배율 OCR로 읽는다. 두 숫자 모두 읽기 일치·신뢰도 0.95 이상이고 지원 박자여야 확정한다. 음가 합계를 근거로 박자표를 추측하지 않는다.
- `recognition.js`, `importPdfTab.js`: 인쇄된 박자표를 다음 staff와 페이지에 전달하고 실제 박자로 마디를 검증한다.
- `scoreAdapter.js`, `scoreMeters.js`, `scoreModel.js`: 해당 마디의 길이로 변환·검증하며 9/8, 12/8을 지원한다. 확정된 반복 운지 생략과 원래 음가를 유지한다.
- `tabSymbols.js`: TAB 선에 붙은 직사각형 쉼표와 기둥 없는 온음표의 떨어진 점을 판별한다. 부족한 박자를 계산해서 쉼표를 채우지 않는다.
- `zoomConsensus.js`: 서로 다른 박자로 검증한 확대 결과가 기존 마디를 대체하지 못하게 한다.

곡명, 파일명, 특정 마디 번호, 정답 운지는 인식 코드에 넣지 않았다. 제작실 통합 검증에서는 같은 PDF 바이트를 임의 UUID 파일명으로 선택했다.

변경 후 69마디 모두 12/8 음가 합계와 인식 신뢰도 검증을 통과했다. 이는 내부 검증 결과이며 모든 표기 요소의 정답률 100%를 뜻하지 않는다.

원본과 따로 비교한 사례:

- 4·29마디: 4분 → 8분 → 연결된 8분 세 개 → 4분 → 2분쉼표. 별도 셋잇단음 표시가 없으므로 3:2 셋잇단음으로 만들지 않는다.
- 50–65마디: 각 마디의 4분·8분 교대 8개 이벤트와 첫 운지 이후 생략 슬래시 7개, 총 112개를 확인했다.
- 25·66–69마디: 점온음표를 확인했다.
- 제작실의 4마디 렌더링: 독립 꼬리 1개, 연결 빔 선분 2개, 쉼표 1개, 반복 운지 슬래시 5개.

다른 PDF의 전체 마디별 음가·점·셋잇단음·쉼표·확정 프렛/현·리듬 검증 결과는 이전 결과와 동일했다:

| 파일 | 비교 마디 | 미확정 항목 | 검토 필요 마디 |
|---|---:|---:|---:|
| 모든 날 모든 순간 | 57 | 0 | 0 |
| 소나기 | 63 | 9 | 2 |
| 바람이 불어오는곳 | 20 | 262 | 20 |
| Flower Dance | 63 | 278 | 37 |

Flower Dance는 기존 릴리스 분석 결과와 비교했다. 이번 변경으로 해당 파일의 기존 미확정 항목이 해결된 것은 아니다.

## 실행한 검증

- `npm test`: 1,578개 통과, 실패 0.
- `npm run build`: 통과.
- `scripts/verify-pdf-tab-compound-ui.mjs`: production preview에서 실제 PDF 선택 → 3페이지 분석 → 제작실 열기 → 브라우저 저장 → 다시 불러오기 → 악기 재생 확인. 브라우저 오류 0. 저장 과정에서 계산되는 MIDI 음높이를 포함한 모든 이벤트를 대조했다.
- 사용자 브라우저와 분리된 테스트 브라우저를 사용했다. 사용자가 저장한 기존 초안은 변환하지 않았다. 새 인식 결과는 PDF를 다시 불러올 때 적용된다.

원본 PDF와 악보 이미지·운지 데이터는 배포 파일에 포함하지 않는다. 상세 실행 로그와 스크린샷은 로컬의 `artifacts/pdf-tab-compound/`, 파일별 분석 비교는 `artifacts/pdf-tab-folder/compound-before/` 및 `compound-after/`에 있다.
