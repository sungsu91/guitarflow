# PDF·사진 TAB 초안 가져오기

최신 변경(2026-10-03): [오선보 → 6현 TAB 및 여러 사진 가져오기](staff-to-tab-batch-2026-10-03.md). 실제 가져오기 화면에 오선보 모델을 연결하고, 여러 사진을 페이지 순서대로 한 악보로 가져오도록 확장했다. 아래의 과거 6현 TAB 전용 제한은 해당 인식 경로의 설명이다.

2026-10-03 공개 전 안정성 검사: [오류 주입·수정·남은 제한 보고서](pdf-tab-release-audit-2026-10-03.md). 작업자 초기화/실행 중 오류와 취소, 화면 전환, 누락 페이지 안내, 회전된 네이티브 숫자 방어를 검증했다.

2026-10-03: 글꼴·저해상도·흐린 빔·확대 복구 보완과 자체 코퍼스 검증은 [인식 보완 보고서](pdf-tab-robustness-2026-10-03.md)를 참조한다. 확대 재분석은 네이티브 텍스트의 미확정 리듬과 TAB을 검출하지 못한 페이지도 포함한다.

악보 제작실의 **PDF·사진 → TAB**에서 PDF를 선택하면 모든 페이지를 자동 분석하고 하나의 새 악보로 연다. JPG·JPEG·PNG는 한 장씩 미리보기에서 방향을 확인하고 **사진 분석**을 누른다. 모바일은 상단 **PDF ▾ → 불러오기(전환)**에서 같은 기능을 사용하며, **악보 사진 촬영** 입력도 제공한다. **PDF 저장**은 기존 인쇄 미리보기로 연결된다. 분석·취소·초안 생성 상태는 `usePdfTabImport`로 공유하고 가져오기·검토 UI는 모바일과 데스크톱으로 나누어 조건부 렌더링한다. 기존 문서와 미저장 편집은 저장 확인 절차로 보호한다. 편집 유지 후 다시 열 때 분석 결과와 초안 ID가 유지된다.

모바일은 분석 진행률·취소·오류·결과를 전용 모달에 표시한다. 가져온 뒤에는 접을 수 있는 PDF 검토 도구로 미확정 위치 이동과 현재 마디 확인을 지원한다. 브라우저 저장 실패 시 파일로 보관하는 안내도 표시한다. 모바일 화면 검증은 320·390·440px Chrome 에뮬레이션이며 실제 휴대폰의 메모리·속도 검증은 별도다. `scripts/verify-mobile-pdf-menu.mjs`는 메뉴·인쇄 미리보기·실제 PDF 변환·미저장 편집 확인을 재현한다.

## 인식 대상

목표는 **실제 TAB 6줄에 놓인 프렛 숫자·X 뮤트와 그 TAB에 연결된 리듬**이다. 제목·QR·가사·코드 다이어그램·오선보는 읽지 않는다. 코드 다이어그램의 세로선을 TAB의 stem으로 잘못 선택하지 않도록 TAB 가장자리와의 연결 거리, 숫자 열과의 정렬을 검증한다. 5줄 오선보와 짧은 격자는 TAB staff에서 제외한다.

1. PDF.js로 기본 3.5배, 페이지당 최대 1,200만 픽셀로 렌더링한다. 이미지 TAB에 미확정이 남으면 4.5배로 다시 렌더링한다. 구조 검출은 Worker에서 수행한다. 각 TAB 줄과 마디 양쪽 경계를 페이지 좌표로 일대일 대응시킨다. 확대에서 일부 줄이나 마디 경계가 달라져도 그 영역만 제외하고, 나머지 대응 영역의 읽기는 활용한다. 원본의 줄·마디 수와 순서를 유지한다.
2. PDF에 실제 숫자 텍스트가 있으면 위치를 투영하고, 검출된 TAB 현에 정렬된 글자만 사용한다. 제목이나 코드표의 숫자는 프렛이 되지 않는다. 좁게 띄운 독립 숫자는 분리하고 동일 위치의 중복 인쇄 글자는 합친다.
3. 이미지 PDF는 TAB 숫자 크기의 후보 영역만 로컬 Tesseract로 처리한다. 최대 일곱 가지 크기·분할·이진화 조건으로 읽는다. 기존 두 읽기가 부족하면 24·36·48픽셀의 작은 글자용 단일 줄/문자 모드도 비교한다. 다른 크기에서 두 번 일치해야 확정하며 유력한 반대 숫자는 그대로 충돌로 남긴다. 작은 입력의 여백은 기존 크기로 유지하고 확대 입력만 캔버스를 넓힌다. 현 위치, 숫자 폭·분리 상태와 일치 여부를 검증한다. 같은 페이지의 확정 숫자 두 개 이상과 모양이 일치하고 다른 숫자와 충분히 구별되면 약한 OCR을 재확인한다. 복구한 숫자를 다시 학습 예시로 쓰지 않으며, 다른 PDF로 예시를 넘기지 않는다. 확대 전후에는 마디·현·열이 일대일로 대응하는 후보만 읽기를 보완한다. 각각 0.90 이상으로 일치하고 유력한 다른 숫자가 없으면 교차 해상도 근거로 확정 점수 0.95를 부여한다. 한 해상도에서만 강하게 읽힌 경우도 반대쪽에 유력한 충돌이 없으면 해당 위치의 읽기를 보완한다. 분석 결과에 원래 점수와 예시·확대 근거를 별도로 보존한다. 기존 확정 운지·쉼표·검증된 리듬을 잃는 확대 마디는 채택하지 않으며, 두 결과의 음표를 이어 붙이지 않는다. 잘린 쉼표를 7로 읽는 경우는 윗부분 형태 검사로 제외한다.
4. 숫자와 리듬은 독립적으로 보존한다. 리듬 합이 맞지 않아도 검증된 프렛과 현은 삭제하지 않는다. 서로 다른 현의 같은 열은 한 동시음으로 묶는다.
5. TAB에 연결된 stem·beam으로 4분·8분·16분, 위/아래 방향의 단독 8분·16분 깃발을 읽는다. 빔에는 더 어두운 임계값을 사용하여 흐린 빔 사이 틈이 합쳐지는 현상을 줄인다. 줄기 끝 바깥의 피킹 표시는 빔에서 제외하고, 줄기의 1~2픽셀 끊김만 좁게 연결해 실제 끝을 찾는다. 짧은 두 번째 빔도 16분으로 구분한다. 아래 줄기 끝의 작은 갈고리 형태 TAB 꼬리도 읽는다. 동일 기준선의 짧은 2분 stem과, PDF에 실제 인쇄된 `3`이 있는 3:2 셋잇단도 지원한다. 간격만으로 음가를 추측하지 않는다.
6. 숫자 텍스트가 확인된 TAB에서는 명확한 8분·온쉼표와 점음표를 모양으로 구별한다. 이미지 TAB도 가운데 현 사이에 인쇄된 4분·8분·16분쉼표를 전체 모양으로 검사한다. 숫자처럼 현 위에 놓였거나 같은 열에 다른 운지/줄기가 있으면 채택하지 않는다. 쉼표로 확인된 조각은 숫자 OCR에서 제외한다. 마디 합계에 맞추어 쉼표를 만들어 넣지 않는다. 리듬이 있는 페이지의 단독 stemless 동시음은 온음표로 처리한다. 숫자만 있는 TAB 페이지는 이 규칙에서 제외한다.
7. 텍스트 PDF와 이미지 PDF 모두, 같은 TAB 안의 반복 슬래시와 연결된 stem을 확인하면 직전에 읽은 동시음 운지를 그 위치에 적용한다. 새 운지가 등장하면 변경하며, 불명확한 운지 뒤에는 복제하지 않는다. 코드 다이어그램에서 운지를 가져오지 않는다. 반복 운지는 `method`/`repeatedFrom`에 근거를 남긴다. 확정된 동시음에는 반복 운지 표기를 활성화한다. 첫 운지와 바뀐 운지는 숫자로 보이고, 바로 이어지는 같은 운지는 슬래시와 원래 리듬으로 보인다. 쉼표·X·단음·미확정 운지 뒤로는 이전 코드를 복제하지 않는다. 실제 음 데이터는 보존하므로 오선보와 재생도 유지된다.

OCR 엔진·WASM·언어 데이터는 `postinstall`/`prebuild`에서 `public/tab-ocr`에 복사한다. PDF나 이미지 조각을 외부 서비스로 전송하지 않는다. 완전히 동일한 숫자 조각의 OCR 결과를 메모리에 보관하여 반복 가져오기를 빠르게 한다. 최근 사용 순으로 관리하며 문자열 기준 32MiB/20,000개를 넘기면 오래된 항목을 비운다. 객체 관리 오버헤드는 별도다. 페이지를 닫으면 사라진다. 확정 0.95/보류 0.75 등의 confidence는 근거 점수이며 보정된 정확도 확률이 아니다.

## 검토와 저장

X/x는 해당 현의 뮤트 음으로 저장하며 0프렛 소리와 구분한다. 프렛 범위는 0~24, 초안의 기본 박자는 **4/4**이다. 문서의 `pdfTabImport`, 마디·이벤트의 `pdfImport`, 음의 `confidence`/`source`에 원본 페이지·staff·마디·렌더 픽셀 좌표와 판단 근거를 저장한다.

- 숫자 미확정 위치에 작은 `?`를 표시한다. 숫자는 읽혔고 리듬만 미확정이면 해당 숫자에 `?`를 덮지 않고 마디 검토 상태로 안내한다.
- 명확히 읽힌 음가가 편집 마디에 들어가면 유지한다. 음가를 결정할 수 없는 마디에는 **임시 편집 격자**를 사용한다. `recognizedDuration`과 `placeholderOnly`로 원본 판단과 임시 배치를 구분한다. 임시 음가는 정답을 뜻하지 않는다.
- 미확정 빈 이벤트는 무음 편집 칸이며, 인식한 쉼표가 아니다. 명확히 인식한 쉼표는 실제 쉼표로 저장한다. 사용자가 남은 음표·쉼표를 채우고 4박 합계를 맞춘 뒤 **현재 마디 검토 완료**로 확정한다.
- PDF 초안은 미확정이 남아도 **현재 입력된 운지로 미리 재생**할 수 있다. `?`는 무음이며 미확정 리듬은 임시 배치대로 들린다. 현·프렛·튜닝·카포에서 음높이와 오선보를 자동 생성하므로 원본 오선보 OCR은 필요 없다. 처음 열 때 악보 소리를 켜고, 이후 사용자가 끌 수 있다. 겹치는 음표, 잘못된 프렛, 끊어진 타이 등 실제 데이터 오류는 계속 재생을 차단한다. 초안 재생이 검토 완료를 뜻하지 않는다.
- 16개를 초과한 후보 열에 잡음이 섞였으면 검증된 프렛 열을 우선 남기고, 빠진 검토 열은 `unmappedSlots`로 보존한다. 검증된 열 자체가 16개를 넘으면 자동 배치하지 않고 전체 원본 열을 검토 메타데이터로 남긴다.
- PDF는 **전체 페이지를 최대 512마디까지 하나의 문서**로 연다. 일반 수동 악보의 기존 64마디 한도와 구분한다. 마디·음표 ID와 원본 페이지/전체 마디 번호를 각각 유지한다. 편집·복사·저장·다시 열기도 같은 한도를 사용한다. 512마디를 넘으면 일부만 생성하지 않고 오류를 표시한다.
- 데스크톱 분석 결과에 페이지별 마디 수를 표시한다. 데스크톱 제작실의 **원본 페이지로 이동**으로 해당 페이지 첫 마디를 선택하고 악보를 스크롤한다. 후반 페이지가 앞의 마디를 재사용하지 않는다.

## 남은 제한

최대 40MB/20페이지/512마디를 처리한다. 기본 박자는 4/4이며 다른 박자·박자 변경·주법·복잡한 다성부·이미지 셋잇단 표시는 지원하지 않는다. 조표·템포·튜닝·카포도 수동 확인 대상이다. 이미지 쉼표는 위의 위치·모양 조건에 한정하며 모든 기보 방식을 포괄하지 않는다. 일반 점음표·줄기 없는 단독 온음표 판별은 숫자 텍스트가 확인된 TAB에 한정한다. 이미지 반복 슬래시의 점은 별도 맥락에서 검사하며, 일반 이미지 음표 꼬리를 점으로 바꾸지 않는다.

TAB에 리듬이 없고 오선보에만 있는 파일은 숫자만 가져온다. 여러 기타 파트가 함께 있는 PDF는 파트 구분이 없으므로 감지된 TAB 영역 순서대로 나열되며, 단일 파트 완성 악보로 사용할 수 없다. 흐린 숫자, 줄·줄기·워터마크와 겹친 숫자는 여전히 누락될 수 있다. 전체 정답률이 보장되는 범용 변환기가 아니다.

개발/배포 환경 모두 가져오기 화면에서 디버그 체크와 하단 개발 안내를 표시하지 않는다. 내부 분석 API의 `debug` 옵션은 로컬 진단 스크립트만 사용할 수 있다.
