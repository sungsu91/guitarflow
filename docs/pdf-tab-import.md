# 데스크톱 PDF TAB 초안 가져오기

악보 제작실의 **PDF에서 TAB 초안 생성**에서 PDF를 선택하면 모든 페이지를 자동 분석하고 하나의 새 악보로 연다. 개발용 체크·범위 선택은 없다. 분석 로직과 악보 데이터는 공유 계층에 두고, 가져오기 모달·검토 도구는 데스크톱에서만 조건부 렌더링한다. 기존 문서와 미저장 편집은 기존 저장 확인 절차로 보호한다.

## 인식 대상

목표는 **실제 TAB 6줄에 놓인 프렛 숫자와 그 TAB에 연결된 리듬**이다. 제목·QR·가사·코드 다이어그램·오선보는 읽지 않는다. 코드 다이어그램의 세로선을 TAB의 stem으로 잘못 선택하지 않도록 TAB 가장자리와의 연결 거리, 숫자 열과의 정렬을 검증한다. 5줄 오선보와 짧은 격자는 TAB staff에서 제외한다.

1. PDF.js로 최대 3.5배, 페이지당 최대 850만 픽셀로 렌더링한다. 구조 검출은 Worker에서 수행한다.
2. PDF에 실제 숫자 텍스트가 있으면 위치를 투영하고, 검출된 TAB 현에 정렬된 글자만 사용한다. 제목이나 코드표의 숫자는 프렛이 되지 않는다. 좁게 띄운 독립 숫자는 분리하고 동일 위치의 중복 인쇄 글자는 합친다.
3. 이미지 PDF는 TAB 숫자 크기의 후보 영역만 로컬 Tesseract로 처리한다. 두 크기·분할 모드의 읽기가 일치하고 문자 confidence, 현 위치, 숫자 폭·분리 상태가 검증되어야 프렛을 채운다. 잘린 쉼표를 7로 읽는 경우를 막기 위해 잘리기 전 윗부분 형태도 검사한다.
4. 숫자와 리듬은 독립적으로 보존한다. 리듬 합이 맞지 않아도 검증된 프렛과 현은 삭제하지 않는다. 서로 다른 현의 같은 열은 한 동시음으로 묶는다.
5. TAB에 연결된 stem·beam으로 4분·8분·16분, 단독 8분 깃발을 읽는다. 짧은 두 번째 빔도 16분으로 구분한다. 동일 기준선에 맞는 짧은 2분 stem과, PDF에 실제 인쇄된 `3`이 있는 3:2 셋잇단도 지원한다. 간격만으로 음가를 추측하지 않는다.
6. 숫자 텍스트가 확인된 TAB에서는 명확한 8분·온쉼표와 점음표를 모양으로 구별한다. 리듬이 있는 페이지의 단독 stemless 동시음은 온음표로 처리한다. 숫자만 있는 TAB 페이지는 이 규칙에서 제외한다.
7. 같은 TAB 안의 반복 슬래시와 연결된 stem을 확인하면 직전에 읽은 동시음 운지를 그 위치에 적용한다. 새 운지가 등장하면 변경하며, 불명확한 운지 뒤에는 복제하지 않는다. 코드 다이어그램에서 운지를 가져오지 않는다. 반복 운지는 `method`/`repeatedFrom`에 근거를 남긴다.

OCR 엔진·WASM·언어 데이터는 `postinstall`/`prebuild`에서 `public/tab-ocr`에 복사한다. PDF나 이미지 조각을 외부 서비스로 전송하지 않는다. `config.js`에서 확정 0.95/보류 0.75, 파일·페이지·후보 한도를 관리한다. confidence는 보정된 정확도 확률이 아니다.

## 검토와 저장

프렛 범위는 0~24, 초안의 기본 박자는 **4/4**이다. 문서의 `pdfTabImport`, 마디·이벤트의 `pdfImport`, 음의 `confidence`/`source`에 원본 페이지·staff·마디·렌더 픽셀 좌표와 판단 근거를 저장한다.

- 숫자 미확정 위치에 작은 `?`를 표시한다. 숫자는 읽혔고 리듬만 미확정이면 해당 숫자에 `?`를 덮지 않고 마디 검토 상태로 안내한다.
- 명확히 읽힌 음가가 편집 마디에 들어가면 유지한다. 음가를 결정할 수 없는 마디에는 **임시 편집 격자**를 사용한다. `recognizedDuration`과 `placeholderOnly`로 원본 판단과 임시 배치를 구분한다. 임시 음가는 정답을 뜻하지 않는다.
- 미확정 빈 이벤트는 무음 편집 칸이며, 인식한 쉼표가 아니다. 명확히 인식한 쉼표는 실제 쉼표로 저장한다. 사용자가 남은 음표·쉼표를 채우고 4박 합계를 맞춘 뒤 **현재 마디 검토 완료**로 확정한다. 미확정 마디가 있으면 초안 저장은 가능하고 재생은 보류한다.
- 16개를 초과한 후보 열에 잡음이 섞였으면 검증된 프렛 열을 우선 남기고, 빠진 검토 열은 `unmappedSlots`로 보존한다. 검증된 열 자체가 16개를 넘으면 자동 배치하지 않고 전체 원본 열을 검토 메타데이터로 남긴다.
- PDF는 **전체 페이지를 최대 512마디까지 하나의 문서**로 연다. 일반 수동 악보의 기존 64마디 한도와 구분한다. 마디·음표 ID와 원본 페이지/전체 마디 번호를 각각 유지한다. 편집·복사·저장·다시 열기도 같은 한도를 사용한다. 512마디를 넘으면 일부만 생성하지 않고 오류를 표시한다.
- 분석 결과에 페이지별 마디 수를 표시한다. 제작실의 **원본 페이지로 이동**으로 해당 페이지 첫 마디를 선택하고 악보를 스크롤한다. 후반 페이지가 앞의 마디를 재사용하지 않는다.

## 남은 제한

최대 40MB/20페이지/512마디를 처리한다. 기본 박자는 4/4이며 다른 박자·박자 변경·주법·복잡한 다성부·이미지 셋잇단 표시는 지원하지 않는다. 조표·템포·튜닝·카포도 수동 확인 대상이다. 위의 쉼표·점·온음표·반복 슬래시 형태 규칙은 숫자 텍스트가 확인된 TAB에 한정하며 모든 기보 방식을 포괄하지 않는다.

TAB에 리듬이 없고 오선보에만 있는 파일은 숫자만 가져온다. 여러 기타 파트가 함께 있는 PDF는 파트 구분이 없으므로 감지된 TAB 영역 순서대로 나열되며, 단일 파트 완성 악보로 사용할 수 없다. 흐린 숫자, 줄·줄기·워터마크와 겹친 숫자는 여전히 누락될 수 있다. 전체 정답률이 보장되는 범용 변환기가 아니다.

개발/배포 환경 모두 가져오기 화면에서 디버그 체크와 하단 개발 안내를 표시하지 않는다. 내부 분석 API의 `debug` 옵션은 로컬 진단 스크립트만 사용할 수 있다.

## 검증 재현

```powershell
npm install
node --test tests/pdf-tab-import.test.mjs
npm test
npm run build
# 별도 터미널에서 Vite를 5174 포트로 실행
$env:PLAYWRIGHT_MODULE='file:///.../playwright/index.mjs'
$env:PDF_TAB_TEST_FOLDER='C:/Users/User/Desktop/sheet music'
node scripts/compare-pdf-tab-folder.mjs whole
node scripts/verify-pdf-tab-folder-ui.mjs
node scripts/verify-pdf-tab-ui.mjs
```

폴더 비교 스크립트는 실제 브라우저의 PDF 파일 입력, importer, 제작실 adapter를 실행한다. 첫 실행에 폴더 목록을 만들고 이후 같은 목록으로 비교한다. 검증 스크립트의 기본 파일 인덱스·수기 정답은 이번 10개 PDF 목록 기준이다. `before` 모드는 로컬에 보관한 수정 전 parser snapshot이 있어야 실행할 수 있다.

실제 PDF, 렌더링 이미지, 분석 JSON은 Git에서 제외된 `artifacts/pdf-tab-folder`에 보관하며 배포 자산에 포함하지 않는다. 실제 비교 수치와 검증 범위는 [검증 보고서](pdf-tab-import-verification.md)를 참조한다.
