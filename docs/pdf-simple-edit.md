# PDF 간단 편집

보관함 카드의 **간단 편집**, 또는 PDF 연습 화면의 **간단 편집**에서 연다.

- **여백 자르기**: 남길 영역의 왼쪽 위와 오른쪽 아래를 차례로 클릭/터치한다. 현재 페이지만 적용한다. 다시 자르기를 열면 원본 전체와 기존 자르기 경계가 보이며, **여백 복원**으로 원래 페이지를 복원한다.
- **마디 설정**: 기존 두 점 지정, 1~4마디 즉시 분할(추가 메뉴 5~16), 같은 줄 높이 맞춤, 복사·삭제, 박 수와 반복 순서를 재사용한다.
- **텍스트 메모**: 악보의 위치를 누르고 문구·크기·색상을 입력해 저장한다. 기존 메모를 눌러 수정·삭제할 수 있다. 메모 편집 중 악보의 다른 곳을 누르면 위치가 바뀌고, 저장할 때 확정한다.
- **↶ / ↷**: 이번 편집 세션의 마디 추가·삭제, 자르기, 메모 변경을 최대 60단계 복구한다. 브라우저 재시작 후 편집 이력 자체는 복원하지 않는다.

## 저장과 좌표

기존 IndexedDB `scores` 레코드에 선택적 `pageEdits`를 추가한다. DB 버전과 `files`의 원본 PDF Blob은 유지한다. 기존 레코드에 필드가 없으면 편집이 없는 상태로 연다.

```js
pageEdits: {
  1: {
    crop: { x: 0.05, y: 0.08, width: 0.9, height: 0.84 }, // null이면 전체
    notes: [{ id: 'uuid', x: 0.2, y: 0.3, text: '천천히', size: 0.035, color: 'brown' }]
  }
}
```

모든 좌표는 원본 페이지 대비 비율이다. 기존 `barMap`도 동일한 기준을 유지한다. 자르기 시 PDF.js 렌더 transform과 canvas 크기만 조정하고, 화면의 마디·메모 좌표는 투영한다. 입력은 역변환한다. 따라서 자르기/복원/화면 크기 변경이 원래 마디나 메모 데이터를 이동시키지 않는다. 잘라낸 영역 밖의 주석은 삭제되지 않고 숨겨진다.

기존 저장 큐·실패 안내와 보관함 백업을 재사용한다. 저장 전 메모가 있으면 페이지 이동·도구 전환·나가기를 안내하고, 저장 또는 취소를 요구한다. 백업 복원의 metadata 정규화에도 주석을 포함한다. 메모의 텍스트는 React 텍스트로 표시하며 HTML로 삽입하지 않는다.

**원본 PDF 내보내기에는 주석과 자르기가 포함되지 않는다.** 이 정보까지 보관하려면 보관함 백업을 사용한다. 주석을 평탄화한 새 PDF 내보내기, 자유곡선 필기, 원본 음표 수정은 이번 구현 범위에 포함하지 않는다.

## 연속 페이지 보기

보기 방식과 배율을 분리했다. **전체 페이지 · 세로**는 1페이지부터 마지막 페이지까지 아래로 이어지는 보기이며, 선택 시 너비 맞춤으로 시작한다. **페이지 너비 맞춤**은 화면 폭에 맞추고, **한 페이지 맞춤**은 한 장의 높이와 폭을 모두 화면에 맞춘다. **100% · 고정 배율**은 화면 크기에 관계없는 렌더 배율이므로 좁은 화면에서 가로 스크롤이 필요할 수 있다.

`PdfContinuous.jsx`가 하나의 PDF.js 문서를 공유하고 현재 페이지와 양옆 한 페이지씩만 기존 `PdfPage`로 렌더링한다. 나머지는 페이지별 종횡비와 자르기를 반영한 자리만 유지한다. 보기 방식은 기존 PDF metadata의 `viewMode`에 저장한다. 스크롤로 현재 페이지를 갱신하며 번호 입력·이전/다음·재열기 위치도 연결한다. 마디와 메모의 원본 좌표 구조는 동일하다.

`scripts/verify-pdf-continuous.mjs`: 390×844/1440×1000에서 24페이지 정렬, 최대 3개 캔버스, 스크롤/번호 이동, 너비 맞춤, 2페이지 메모 저장, 보기 방식·3페이지 재열기를 통과했다. 단일 페이지 간단 편집 회귀 검사와 10개 PDF 단위 검사, 빌드도 통과했다.
