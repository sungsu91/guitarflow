# 에튀드 악보 편집 · 데이터 v2

2026-09-13. 기존 폼 편집기, 코드표, VexFlow SVG, JSON 입출력을 확장했다. 이미지 원본이나 별도 악보 시스템을 만들지 않았다. 조작 비교의 근거와 미확인 사항은 [구현 전 비교표](etude-editor-benchmark.md)에 기록했다.

## 화면에서 입력

- 기본곡의 **악보 편집**은 독립적인 사용자 복사본을 연다. 보관함에서 **빈 악보 만들기**, 저장본 열기, 복사해 편집을 할 수 있다.
- TAB 클릭은 현재 박/줄에 커서만 옮긴다. 숫자 0–9가 선택 위치에 입력된다. 같은 위치에서 700ms 안에 입력한 두 숫자는 0–24 범위에서 합쳐진다. 700ms는 FRETIVA의 설정이며 GP의 수치라고 확인된 것은 아니다.
- 좌우는 기존 이전/다음 이벤트, 위아래는 TAB 줄, Tab은 오선/TAB 전환이다. 끝에서는 멈춘다. 마디 추가는 명시적인 버튼이다.
- + 또는 =는 짧게, -는 길게, R은 쉼표, Delete/Backspace는 현재 줄의 음 삭제다. 음이 모두 없어지면 같은 길이의 쉼표로 남는다. 음표 이벤트 자체 삭제는 속성 패널에서 한다.
- H는 다음 프렛 방향에 따른 해머온/풀오프, S는 슬라이드다. 연결이 불가능하면 상태를 표시한다. Ctrl/Cmd+Z, Shift+Z 또는 Ctrl+Y로 실행 취소/다시 실행, Ctrl/Cmd+S로 저장한다.
- 다른 줄에 숫자를 입력하면 같은 박의 동시음이 된다. 새 박은 **뒤에 박 삽입**, 새 마디는 빈 마디 추가로 넣는다. 박 삽입과 음표 복제는 같은 마디의 뒤쪽 이벤트를 삽입 길이만큼 명시적으로 밀고, 다른 마디는 유지한다. 마디를 초과하면 경고한다. **현재 박 나누기**는 현재 음을 절반 길이로 줄이고 뒤 절반에 쉼표 입력 자리를 만들어 전체 마디 길이를 유지한다. 연결된 박은 먼저 연결을 해제해야 한다. 일반 음 길이 변경·삭제는 후속 음의 시점을 자동으로 밀거나 당기지 않는다. 발생한 빈 박/겹침/초과는 경고되며 시작 시점 속성으로 명시적으로 수정한다.
- 오선 클릭도 선택만 한다. 선택한 음높이에서 1–6으로 기타 줄을 지정한다. 0/음정 적용은 기존 줄을 유지할 수 있으면 유지하고, 그렇지 않으면 가능한 줄·프렛을 제시한다. GP의 공개되지 않은 자동 최적화 엔진은 구현했다고 주장하지 않는다.
- **Alt+위/아래**는 Soundslice를 참고한 동일음 줄 이동이다. 예: 2번줄 5프렛 ↔ 3번줄 9프렛. 음높이는 유지된다. 사용자가 입력한 운지는 잠기며 주변 음 변경으로 다시 계산되지 않는다.
- 모바일은 악보 입력/선택 음 속성을 조건부로 나눈다. 숫자 키패드, 화살표, 길이·쉼표는 악보에서 사용한다. 나머지 기법·마디 도구는 속성의 접는 패널에 있다. 데스크톱은 악보 옆 기존 속성 패널을 유지한다.

## 부분 수정·저장

기본곡은 덮어쓰지 않는다. 수정본/신규 악보는 `fretiva.etude.library.v2`의 문서 ID별로 저장한다. 교육 검수와 난이도를 사용자 입력에 자동 보증하지 않는다. 화면에 사용자 편집본임을 표시한다. 미완성 문서도 **초안**으로 저장하며 오류가 있으면 재생을 보류한다. 원본 복원은 현재 편집본에 기본 내용을 가져오는 Undo 가능한 동작이며 다른 저장본을 지우지 않는다.

저장 여부·실패를 표시하고, 닫을 때 미저장 변경을 확인한다. 브라우저 새로고침/종료에는 beforeunload 경고를 요청한다. 모바일 OS의 강제 종료에서 경고가 보장되는 것은 아니며 자동 저장/기기 간 동기화는 없다. 중요한 작업은 저장 또는 파일 내려받기로 보관한다. 기존 v1 저장 키는 삭제하지 않으며 이관 실패 시 덮어쓰지 않는다. 읽기 어려운 저장 레코드도 원자료를 유지한다.

구간 복사/붙여넣기는 **마디 단위**이며 Ctrl/Cmd+C/V도 같은 선택 범위를 사용한다. ID는 새로 부여하고 범위 내부 붙임줄을 새 ID로 연결한다. 범위 밖 연결은 검사 대상으로 남긴다. JSON 파일 입출력은 기존 기능을 유지한다.

## 단일 음악 원본

`format: fretiva.etude`, `version: 2` 문서:

- 곡: `id`, `templateId`, `kind`, `origin: {templateId, revision}`, 제목·설명·TIP·BPM, `meter`, `keySignature`, `tuning`.
- 마디: 안정적인 `id`, 코드표/화음명, `events`.
- 이벤트: 안정적인 `id`, `onset`(4분음표=480 ticks), `duration`, `rest`, `technique`, `notes[]`, 선택적 `tieTo`와 피킹 방향.
- 동시음: 동일 이벤트의 `notes[]`. 각 음은 `id`, `string`, `fret`, `locked`, 선택적 이명동음 표기와 양손 손가락 번호다. 음별 독립 길이를 갖는 다성부는 아직 없다.

실제 MIDI = tuning[string-1] + fret. 오선보·TAB·합성 재생은 동일 컴파일 결과를 사용한다. 기타 오선은 실음보다 한 옥타브 높고 8vb 높은음자리표를 사용한다. TAB 직접 수정은 예전 음이름 철자를 해제해 새 음높이로 계산한다. 음정 변경 시 다른 마디의 운지를 재선택하지 않는다. 조표 변경은 실제 음을 조옮김하지 않는다. 사용자 반음/비화성음에는 교육용 음계 제한을 적용하지 않는다.

튜닝 저장 순서는 **1→6번줄**, 기존 코드표 frets/fingers 배열은 **6→1번줄**이다. 코드표 화면은 1번줄이 위, 프렛은 오른쪽으로 증가한다. 코드표 프렛 수정은 안내된 대로 그 마디 해당 줄의 음에도 적용한다.

`scoreDocument.js`의 v1 호환 경로/코드표 수정/입출력을 유지했다. `scoreModel.js`가 v2 컴파일·불변 부분 수정·후보 계산을 제공하고, `scoreLibrary.js`는 기존 저장본 이관과 다중 편집본 저장을 담당한다. 기본곡도 생성 템플릿을 한 번 문서로 구체화한 뒤 같은 컴파일러를 통과한다. 개발자 수정은 전체 템플릿 재생성이 아니라 문서 override로 적용할 수 있다.

## 입력 조작 보완

- 초기화 메뉴에서 편집창을 열 때의 상태로 복귀하거나, 제목·박자·튜닝을 유지한 빈 한 마디로 비울 수 있다. 둘 다 Undo 가능하고 저장 전까지 보관함 원본은 바뀌지 않는다.
- 확대/축소는 25·50·67·75·90·100·125·150·200%를 제공한다. 모바일 최소 너비도 비율에 따라 줄어들어 100% 이하에서도 실제로 축소된다.
- 클릭은 음표 중심 사이의 중간점을 경계로 가장 가까운 박을 선택하고, TAB 줄 사이 중간점으로 줄을 선택한다. 클릭 영역의 빈틈·중첩을 제거했다. 커서는 넓은 클릭 영역 전체가 아니라 음표/프렛 위치의 작은 사각형이다.
- 피킹 일괄 설정: 전체/현재 마디/지정 마디 범위에 다운→업, 업→다운, 모두 다운, 모두 업, 표시 지우기. 마디 경계에서도 순서를 이어가고 실제 피킹할 이벤트만 센다. 기본적으로 H/P/SL의 도착음, 쉼표, 붙임줄 도착음을 건너뛴다. 기존 범위 내 표시를 교체하며 한 번의 Undo로 복원된다. 운지·음높이·리듬은 바꾸지 않는다.
- 이 피킹 기능은 선택한 반복 규칙을 일괄 적용하는 도구다. 곡에 가장 적합한 피킹을 분석·보증하거나 Guitar Pro의 내부 자동 판단을 복제한 기능은 아니다.

추가 검증: `tests/etude-refinements.test.mjs`, `scripts/verify-etude-refinements.mjs`.


## 앞 삽입과 음표 드래그 (2026-09-13 후속)

- `앞에 박 삽입`은 선택 이벤트의 시점에 같은 길이의 쉼표를 넣고 선택 이벤트부터 같은 마디의 뒤쪽만 민다. `뒤에 박 삽입`은 기존 동작을 유지한다. 새 빈 박이 선택되며 초과 박자는 경고한다. 자동으로 다른 마디를 재구성하지 않는다.
- 음표 머리 또는 TAB 숫자가 드래그 시작점이다. 빈 공간 클릭은 계속 커서 선택만 한다. 음표 사이의 새 입력 자리는 앞/뒤 삽입 또는 박 나누기로 준비한다.
- TAB의 위아래 드래그는 프렛을 유지한 채 줄을 바꾸므로 실제 음높이도 달라진다. 동일 음높이를 유지하는 운지 변경은 기존 Alt+↑↓/운지 후보 도구를 사용한다.
- 오선보의 위아래 드래그는 조표에 맞는 오선 위치로 스냅하고 기존 줄을 유지해 프렛을 계산한다. 같은 높이의 좌우 이동은 원래 임시표 음정을 유지한다. 현재 줄의 0–24프렛으로 낼 수 없는 음은 적용하지 않고 후보 도구를 안내한다.
- 좌우/다른 마디 이동은 같은 길이의 쉼표 자리로 한 음을 옮긴다. 원래 자리는 쉼표가 되며, 동시음 중 하나만 옮겼다면 나머지는 유지한다. 이벤트 ID·시점·길이와 무관한 음 데이터는 유지한다. 이미 음표가 있는 박이나 길이가 다른 박은 덮어쓰지 않는다.
- 붙임줄/H/P/SL 연결 음의 드래그는 연결을 먼저 해제하도록 안내한다. 연결을 조용히 삭제하거나 재지정하지 않는다.
- 드래그 중 DOM 프리뷰와 목적지 표시만 requestAnimationFrame으로 갱신한다. Pointer up에서 한 번의 음악 데이터 변경/Undo를 기록한다. Esc, pointer cancel, 악보 밖 드롭은 내용을 유지한다. 축소율에 맞게 드래그 시작 거리도 조정한다. TAB 손잡이 높이를 줄 간격 이하로 제한해 인접 줄을 가리지 않는다.
- `useScoreDrag.js`가 모바일/데스크톱의 포인터 동작을 공유하고 기존 레이아웃 분리, ScoreEditor history, 저장 및 VexFlow 렌더러를 재사용한다.

검증: 관련 Node 테스트 46개 통과. `scripts/verify-etude-drag.mjs`에서 desktop/mobile viewport, 마우스 드래그, CDP 터치 드래그, 50% 오선 드래그, Escape 취소, Undo/저장, 드래그 중 마디 draw-count 불변을 확인했다. `scripts/verify-etude-refinements.mjs`도 통과. 실제 휴대폰 및 Guitar Pro 앱 조작은 직접 검증하지 않았다.


## 편집 화면 정리 — 사용자 제공 레이아웃 참고

데스크톱은 상단 빠른 도구막대, 왼쪽 입력/주법/마디 패널, 중앙 SVG 악보, 오른쪽 음표/마디/곡 정보 속성으로 배치한다. 왼쪽 줄 선택·프렛 증감·직접 입력, 상단 음 길이 버튼은 기존 enterFret/patchEvent/history를 호출한다. 오른쪽 기존 Controls 폼은 삭제하지 않고 분류별 조건부 렌더링으로 재사용한다. 모바일은 간결한 도구막대와 악보 입력/속성 전환을 유지하며 데스크톱의 양쪽 패널을 강제 노출하지 않는다. 저장 버튼은 헤더에, 파일 입출력·원본 복원은 하단에 둔다. 자동 저장이나 지원하지 않는 주법 버튼을 시안만 보고 추가하지 않았다.

수정 파일: ScoreEditor.jsx, scoreEditor.css, 신규 UI 모듈 EditorInputPanel.jsx. 음악 원본/저장/재생 구조 변경 없음. UI 분류만 전환했을 때 저장 데이터가 동일한지, 빠른 프렛 입력과 음 길이 버튼·Undo가 기존 데이터에 반영되는지 브라우저에서 확인했다. 1440/1024/390/320px 배치 확인, 드래그/초기화/피킹 회귀 시나리오 및 관련 Node 테스트 46개 통과. 스크린샷과 결과는 artifacts/etude-input/toolbar-*에 있다.

상단 정렬 후속: 데스크톱 툴바와 본문이 같은 열 너비 변수를 사용한다. 입력/주법/마디 탭은 왼쪽 패널 위, 빠른 도구막대는 악보 왼쪽부터 속성 패널 오른쪽까지 배치한다. 보조 작업은 더보기에서 열며 모바일 도구막대는 별도 배치를 유지한다. 1440/1024px에서 각 좌우 경계 오차 1px 미만, 390px 모바일 가로 넘침 없음과 더보기/입력 탭 동작을 브라우저로 확인했다.

최신 배치: 사용자 요청으로 요소 속성을 왼쪽 입력 패널 아래로 이동했다. 데스크톱은 왼쪽 도구/속성 한 열 + 오른쪽 악보 두 열 구성이다. 왼쪽은 한 스크롤 영역을 공유하며 상단 툴바는 확장된 악보와 좌우 경계를 맞춘다. 모바일의 악보/속성 전환은 유지한다. 1440/1024px 좌측 배치·툴바 정렬, 390px 속성 전환과 빌드를 확인했다.

최신 고정 레이아웃: 사용자 확인에 따라 입력 / 요소 속성 / 악보 순서로 배치한다. 두 도구 패널은 모두 악보 왼쪽에서 같은 높이로 시작한다. 데스크톱 dialog는 97dvh 고정 flex shell, 본문은 min-height:0으로 남은 높이를 사용하며 악보 canvas만 독립 스크롤된다. 긴 속성/입력 항목은 해당 패널 내부에서만 스크롤 가능하며 전체 창으로 스크롤이 전파되지 않는다. 모바일은 기존 탭 구조를 유지한다. 툴바 보조 메뉴는 overlay로 표시하고 닫기 버튼을 제공한다. 1440×1000, 1440×800, 1024×768에서 dialog clientHeight=scrollHeight, 악보 wheel 후 패널/툴바/하단 좌표 불변을 확인했다. 피킹/초기화/삽입/드래그/Undo 브라우저 회귀 검사와 빌드 통과. 결과는 artifacts/etude-input/fixed-shell.json.

## 덧줄 선택 영역 보완

오선의 덧줄은 VexFlow noteHeads의 실제 위치·폭·덧줄 간격에서 선택 영역을 계산한다. 덧줄 선택 영역에는 소유 음표의 event/string/MIDI를 연결한다. 공유 덧줄은 가까운 음표를 우선하고, 음표 머리를 직접 누르면 해당 머리가 우선한다. 음표와 달리 덧줄 자체를 독립적으로 드래그하지 않는다. 선택 커서는 선택한 화음 구성음의 실제 머리 위치를 사용한다.

모바일 Chrome의 터치 대상 보정이 인접한 음표를 선택하는 경계 사례를 재현했다. useScoreDrag는 실제 pointer 좌표에서 Shadow DOM hit를 확인하고, pointer down에서 선택한 대상을 후속 click이 바꾸지 않도록 처리한다. 기존 편집/저장/재생 데이터와 TAB의 0 입력은 변경하지 않는다.

변경: Score.jsx, EditorScore.jsx, useScoreDrag.js. 회귀 검사 scripts/verify-etude-ledger-hits.mjs는 위/아래 덧줄, 여러 덧줄, 화음의 공유/엇갈린 머리, 실제 개방현, 50/100/150% 배율, 스크롤, desktop mouse/mobile touch에서 총 192회 선택을 확인한다. 선택 후 저장 원본 동일 및 마디 draw-count 불변도 확인한다. 모바일 검사는 Chrome 에뮬레이션이며 실제 휴대폰 검증은 아니다.
