# FRETIVA LAB ko/en 적용 및 검증 보고

한국어 기본값과 English 전환을 적용했다. 새 저장 항목은 `localStorage.language`이며 기존 언어값이 없거나 유효하지 않으면 `ko`를 사용한다. 모바일 메뉴와 데스크톱 설정이 같은 언어 상태를 구독한다.

## 영어 길이와 용어

좁은 공간에는 `Gtr.`, `Rpt.`, `Pick`, `Tech.`, `Beams`, `PDF`, `Clear` 등 문맥에 맞는 짧은 문구를 사용했다. `Hide`는 빔 표시를 숨기는 기능이며 음표나 데이터를 삭제한다는 뜻으로 번역하지 않았다. 관련 전체 설명은 기존 title/aria-label 또는 추가한 접근성 이름으로 제공한다. 버튼 크기·배치·폰트 크기를 조정하지 않았다.

한국어 기준본은 그대로 보존했다. `terminology-audit.json`에는 동일 한국어의 영어 표현이 문맥에 따라 달라지는 24개 그룹과 이유를 기록했다. 예: 선택 동작은 Select, 작곡자 입력의 선택 항목은 Optional, 코드 확장 없음은 None, 기본 임시표는 ♮.

## CSS와 기존 작업 구분

승인받은 변경은 한국어 `aria-label` 기반 선택자를 언어에 독립적인 `data-ui`로 바꾸는 것이다. `etudeRemote.css`, `scoreEditor.css`, `pdfStudio.css`는 줄바꿈을 정규화하면 해당 선택자 변경만 있다.

`practiceLayout.css`는 기준 snapshot의 기존 선언이 모두 동일하지만, 파일 끝에 모바일 아이콘 정렬용 기존 별도 규칙 3개가 추가된 상태다. 이 규칙은 제거하거나 이번 i18n 수정으로 재작성하지 않았다. 따라서 전체 작업 트리 CSS가 기준 snapshot과 오직 선택자만 다르다고 주장하지 않는다. 실제 비교는 `css-verification.json`에 기록했다. 작업 전 수정 및 별도 검증 파일도 유지했다.

## 검증 범위의 한계

실제 휴대전화/Safari, 실제 기타 마이크 신호의 튜너 정확도, 실물 MIDI/오디오 장치, 유료 계정의 모든 PRO/SOLO 조건, 모든 DEV 세부 도구와 모든 오류 발생 경로, OMR 모델 실행은 직접 검증하지 않았다. 이 영역은 소스 조사·문자열 분리·기존 테스트 범위의 확인이며 실기기 검증 완료로 표시하지 않는다. PDF는 생성한 테스트 PDF로 검증했고 개인 파일이나 실제 사용자 저장소를 사용하지 않았다.
