# 오선보 → 6현 TAB 및 여러 사진 가져오기

2026-10-03. 사용자 요구는 오선보 음표를 기타 TAB으로 변환하는 것이었다. 앞선 JPG·PNG 지원은 이미 인쇄된 TAB을 읽는 기능에만 연결되어 있었다. 이번 변경에서 오선보 인식 모델을 실제 가져오기 화면에 연결했다.

## 사용 흐름

모바일은 **PDF ▾ → 불러오기(전환)**, 데스크톱은 **PDF·사진 → TAB**을 사용한다. **오선보 → TAB / TAB → TAB** 중 변환 방식을 선택하고 하나의 파일 선택창에서 PDF 한 개 또는 JPG·PNG 여러 장을 불러온다. 별도의 사진 촬영 항목은 제거했다. 사진은 파일명의 숫자를 기준으로 정렬하며, **사진 추가**, 페이지 선택, **앞으로/뒤로**, 페이지별 **90° 회전**, **삭제**를 지원한다. **사진 전체 분석 → 제작실에서 열기**로 한 악보를 만든다.

사진은 최대 20장·합계 40MB다. PDF와 사진을 한 목록에 혼합하지 않는다. 같은 이름·크기·수정 시각의 사진은 중복 추가하지 않는다. 중간 페이지가 읽히지 않으면 일부만 성공한 것으로 열지 않고 파일명과 페이지 번호를 표시한다. 분석 성공 후에는 다시 분석 버튼을 숨기고 편집기 열기를 제공한다. 오류는 미리보기 아래 작은 글씨 대신 창 위쪽 경고 영역에 표시한다.

오선보 변환은 원본의 음표 위치가 기존 기타 오선보 표시와 일치하도록 변환한다. 사용자에게 음높이/옥타브 선택은 제공하지 않는다. 인식 모델의 기보 음높이를 기타의 실제 연주 음높이로 바꾸는 내부 기준은 렌더러의 표시 기준을 역으로 적용한다(-12반음). 이전에 기본값을 0으로 바꾸면서 원본 B5가 19프렛/B6로 표시되는 회귀가 생겼다. 이를 수정하여 B5 → 7프렛 → 표시 B5로 왕복한다. 운지는 개방현·1~4프렛을 우선하되 음역에 필요한 높은 포지션을 허용한다. 음역 밖의 음은 미배치로 보존한다.

기존 0 기준의 오선보 변환 문서는 제작실의 **원본 음표 위치로 복원**으로 고칠 수 있다. 자동 저장본 변경은 하지 않는다. 리듬·마디·음표 ID·원시 인식 자료를 유지하고, 실행 취소/다시 실행 및 명시적 저장을 지원한다. 사용자가 음높이를 고친 음표나 새로 추가한 음표가 있으면 일괄 복원을 막아 그 편집을 보존한다. TAB → TAB 결과에는 이 복원이 적용되지 않는다.

## 구현과 지원 범위

- 화면에서 **오선보 → TAB**을 선택하면 5줄 오선보를, **TAB → TAB**을 선택하면 6줄 TAB을 읽는다. 오선보와 TAB이 함께 있는 악보는 TAB → TAB을 선택해 기존 운지를 보존한다. 잘못된 변환 방식을 선택해 해당 악보 구조를 찾지 못하면 방식을 바꾸도록 안내한다. 내부 분석 API의 자동 감지는 기존처럼 TAB을 우선하지만 화면 선택은 명시적으로 전달한다.
- 페이지에서 오선보 시스템을 잘라 로컬 CrispEmbed/TrOMR Q8 모델로 읽는다. 가로로 긴 한 줄짜리 악보는 전체 문맥을 유지한다. 조표, 임시표의 마디 내 유지/초기화, 기본 음가, 점음표, 쉼표, 같은 음가의 동시음을 변환한다.
- 서로 길이가 다른 독립 성부나 해석하지 못한 토큰은 원시 결과와 빈 검토 위치를 보존한다. 박자를 맞추려고 임의의 쉼표를 채우거나 인식한 음가를 압축하지 않는다.
- 모든 오선보 결과는 검토 대상이다. 모델이 음별 확률을 제공한 것처럼 신뢰도 수치를 꾸미지 않는다. 출처 좌표는 시스템 단위이며, 음별 정확한 위치를 추정해 원본 좌표로 표시하지 않는다.
- 붙임줄·슬러·D.S./코다·반복 진행은 자동 적용하지 않는다. 읽힌 기본 음표는 순서대로 가져오고, 이 기호들은 원본과 대조해 편집해야 한다. 손가락 번호를 읽는 기능도 아니다.
- 사진 원본을 모두 디코딩한 채 보관하지 않는다. 작은 미리보기만 유지하고, 분석 시 한 장씩 디코딩·처리·해제한다. 하나의 OMR Worker를 시스템/페이지 사이에 재사용하며, 종료·취소·실패·시간 제한 시 종료한다.
- 모델·런타임은 약 36MB이며 필요한 경우에만 브라우저가 로컬 앱 자산으로 로드한다. 사진이나 PDF를 외부 인식 서버에 업로드하지 않는다. 기존 실험에서 WASM heap 약 421MiB가 관찰됐으므로 실제 휴대폰 메모리·Safari 검증은 여전히 별도다.

모델 형식 및 라이선스 근거: [TrOMR 공식 저장소](https://github.com/NetEase/Polyphonic-TrOMR), [CrispEmbed](https://github.com/CrispStrobe/CrispEmbed). MIT/Apache-2.0 라이선스 사본을 런타임과 함께 제공한다. 자산 설치 스크립트는 기존에 검증한 SHA-256과 비교하며 변경된 바이너리를 자동 수용하지 않는다.

## 검증 결과

음높이 회귀 수정 검증: 전체 테스트 1,750개 통과와 빌드 성공. 같은 원시 인식 자료 18시스템·81마디·409음을 기존 오류 기준과 새 기준으로 비교했고, 기존 문서 복원 결과가 새 가져오기의 운지·음높이·리듬과 일치했다. 모바일/데스크톱에서 복원 → 실행 취소 → 다시 실행 → 저장 → 새로고침을 검증했다. 실제 두 JPG를 다시 분석하여 135.8초에 81마디·409음이 생성되었고 첫 음은 7프렛, 표시 B5로 확인했다. 이는 모든 음표·리듬의 정답 판정이 아니다. 원본 인식의 다른 오류와 검토 필요 상태는 유지한다.

배포용 빌드에서도 모바일/데스크톱 PDF → TAB, 기존 문서 복원·실행 취소·저장·새로고침, TAB 사진 두 장 → 8마디를 확인했다. TAB 사진 묶음 검사는 첫 실행에서 120초 UI 대기 시간 초과가 있었고, 빌드 완료 후 재실행은 통과했다. 첫 시간 초과의 원인은 확정하지 않았으며 모든 환경의 처리 시간을 보장하지 않는다.

검증 파일: `scripts/verify-staff-pitch-regression.mjs`, `scripts/verify-staff-production.mjs`, `scripts/verify-staff-photo-ui.mjs`. 회귀 수정 결과는 `artifacts/staff-pitch-regression/`에 분리 보관했다.

사용자가 선택한 `풀잎사랑(코드)_페이지_1.jpg`, `풀잎사랑(코드)_페이지_2.jpg`를 실제 UI에서 역순으로 선택해 정렬·순서 변경·모바일↔데스크톱 전환 후 분석했다.

- 실제 모델로 **2페이지·18개 오선보 시스템 → 81마디·409개 입력 음**을 생성했다. 정답을 인식기에 전달하거나 악보별 변환 결과를 하드코딩하지 않았다.
- 모바일 440px 편집기로 열기와 저장까지 통과했다. G조 및 기타 기보 옥타브 설정, 점음표·동시음·원본 페이지/파일 목록·원시 인식 결과를 보존했다.
- 약 **145초**가 걸렸다. 이는 이 PC의 Chrome 관찰값이며 휴대폰 예상 시간이나 보장값이 아니다.
- 모든 81마디가 미검토 상태다. 문서 구조 컴파일 오류와 브라우저 오류는 없었고 종료 후 남은 Worker는 0개였다. **409개가 모두 정확하다는 뜻은 아니다.** 원본 대조에서 음높이 오류·쉼표 누락·붙임줄 누락이 확인되었다.
- 별도의 독립 정답 C4–D4–E4–F4 한 마디 PDF에서, 타이트한 자르기가 음을 한 옥타브 낮게 읽게 하는 오류를 발견했다. 가로로 긴 한 시스템 입력의 전체 영역을 유지하도록 수정한 후 배포용 빌드에서 음높이·리듬·TAB 배치를 검증했다. 다른 모든 악보의 옥타브 오인식이 해결되었다는 뜻은 아니다.
- 배포용 빌드에서 데스크톱 오선보 PDF → TAB 편집기를 통과했다. 모바일 320px에서 사진 추가·중복 방지·두 TAB 사진을 8마디로 합치기·저장도 통과했다.
- 기존 PDF 정상/이미지 입력, 구조 분석 취소, OCR 초기화 취소, 구조/OCR 작업자 오류 주입 6개를 재검사해 통과했다.
- 전체 테스트 **1,741개 통과, 실패 0개**와 배포용 빌드 성공을 확인했다. 결과는 `artifacts/staff-photo/tests.log`, `build.log`에 기록했다. 기존 큰 번들 경고는 남아 있다.

정확한 자동 완성 기능으로 공개할 수준이라고 판정하지 않는다. 현재 실제로 연결된 기능은 **오선보를 읽어 표준 운지의 편집 가능한 TAB 초안을 만드는 기능**이다. 실제 휴대폰 촬영/파일 선택, 메모리 압박, iOS Safari, 심한 기울기·원근·그림자는 미검증 또는 미보정 범위다.

## 재현

`scripts/verify-staff-photo-ui.mjs`는 위 실제 두 파일을 사용하는 로컬 검증이다. 사용자 파일을 public 또는 배포 산출물로 복사하지 않는다. `scripts/verify-staff-production.mjs`는 자체 제작 악보로 배포용 경로를 검사한다.

```powershell
node scripts/sync-staff-omr-assets.mjs
node --test tests/staff-score-import.test.mjs
# PLAYWRIGHT_MODULE 지정 및 개발 서버 5174 실행 후:
node scripts/verify-staff-photo-ui.mjs
npm test
npm run build
# 4174 preview 서버 실행 후:
node scripts/verify-staff-production.mjs
```

진단 자료는 Git 제외 `artifacts/staff-photo/`에 있다. 원시 인식 문자열은 참고 자료이며 사용자에게 정확한 정답 악보로 제시하지 않는다.


## 초안 재생 차단 수정

실제 재분석 결과의 36마디는 4.25/4박, 41마디는 5/4박으로 읽혀 전체 재생이 차단되었다. 두 마디의 인식 오류 자체를 고쳤다는 의미가 아니다. 검토 전 오선보 변환에서 박자를 초과한 마디만 임시 재생본에서 명시적인 쉼표로 처리하고, 화면과 저장본에는 인식된 음표·길이를 그대로 보존한다. 초안 미리듣기 안내에 무음 마디 번호를 표시한다. 박자를 고치면 자동으로 해당 마디의 소리도 복원된다. 음표 겹침·잘못된 프렛 등 구조 오류와 전체 마디가 재생 불가능한 경우에는 차단을 유지한다.

공유 판정/재생 로직을 사용하고 모바일·데스크톱 안내 화면은 별도로 렌더링한다. 실제 문서의 나머지 391개 연주 음은 원래의 높이·시작 시점·길이와 동일하다. `scripts/verify-staff-playback.mjs`로 배포용 빌드의 모바일/데스크톱 악보연습실과 제작실 모두에서 클릭을 끈 상태의 실제 기타 PCM 출력을 측정했다(peak 약 0.13). 원본 저장 데이터 동일성, 브라우저 오류 0개, 전체 테스트 1,753개 및 빌드 성공을 확인했다. 결과: `artifacts/staff-playback/`.
