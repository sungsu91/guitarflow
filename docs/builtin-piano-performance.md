# 기본 제공 진행 피아노 반주 개선

## 적용 범위

- 리듬코드: `src/rhythm/recommendedProgressions.js`의 기본 진행 7개, `src/rhythm/voicingMovementCourses.js`의 기본 보이싱 연습 15개.
- 미니코드: `src/mini-chord/originalPracticeSongs.js`의 5개 및 앱에 포함된 `personalPracticeProjects.js`의 1개.
- 원본 코드 이름, 코드 순서, 마디, 리듬 패턴, 구간, 반복 기호 데이터는 수정하지 않았다. 기본 진행을 읽은 뒤 **내부 재생 이벤트를 편곡**한다. 사용자 저장소에 연주층을 쓰거나 데이터를 마이그레이션하지 않는다.
- 화면, MobileLayout/DesktopLayout, 편집기, 코드 선택, BPM/반복/이조 조작은 변경하지 않았다.

## 기존 구현 확인 결과

두 화면은 `src/App.jsx`의 `createBackingTimelineEvents`, `prepareStage3BackingSession`, `runBackingScheduler`, `playBackingSample`을 공유한다.

피아노는 `getBackingPianoVoicing`에서 기타 지판 MIDI 보이싱을 먼저 사용하고, 없으면 고정 `BACKING_PIANO_VOICINGS` 또는 루트 기준 화음으로 재생했다. `guideTones` 및 `thirdSeventh` 선택도 있었다. 저장된 기타 자리바꿈은 반영하지만, 앞 코드와 비교해 피아노 자리바꿈 후보를 고르는 기능은 없었다. 모든 코드가 한 옥타브의 동일 강약 화음이었던 것은 아니다.

베이스는 `bass_a.wav`~`bass_g.wav` 별도 샘플이다. 루트뿐 아니라 기존 패턴의 3도·5도·옥타브·7도·다음 루트·반음 접근을 지원했다. 이번 작업에서 이 기존 베이스 패턴을 다시 만들지 않았다.

피아노 샘플은 `public/sounds/gpg4.wav`이다. WAV 헤더는 44,100Hz, 16비트, 스테레오, 약 2.124초이다. 샘플 자기상관에서 약 390.3Hz를 확인했으며 코드의 G4/MIDI 67 기준과 일치한다. 기존 식은 `2 ** ((midi - 67) / 12)`이고 실제 소스 재생속도는 0.25~4로 제한되어 있었다. 이 때문에 C2 등의 낮은 음을 추가할 때 기존 제한을 그대로 사용하면 잘못된 음높이가 된다.

`playbackDynamics.js`에는 이미 CHORD/STAB/HOLD/ARP별 길이·ADSR·음별 강약·결정적인 시간차가 있었다. 일부 basic CHORD 공통음은 약하게 재타격했다. 실제 지속 음을 이어 쓰는 방식은 아니었다. 룸 컨볼루션, 150Hz 하이패스, 18ms 프리딜레이, 0.11 wet, 출력 리미터와 42개 피아노 voice 제한도 있었다.

타이머는 `setInterval(..., 25)`로 스케줄러를 깨우며, 실제 시작·종료 및 게인 곡선은 AudioContext 시간축에 약 180ms 앞서 예약한다. 타이머가 직접 음을 내는 방식이 아니다. BPM으로 박 길이를 산출하고, 반복/도돌이/점프는 기존 재생 순서와 cycle을 사용한다. 변경된 세션은 기존 안전 경계에서 교체한다. 이조는 먼저 코드 이름·루트를 바꾸고 세션을 다시 생성한다.

## 변경된 내부 연주 데이터

공유 모듈은 `src/audio/builtinPianoPerformance.js`이다.

- **bass:** 기존 베이스 악기와 별도로 기존 핵심 피아노 타격에만 가벼운 낮은 루트를 보강한다. MIDI 36~55 안에서 직전 베이스에 가까운 음을 고르고 middle보다 최소 5반음 낮게 둔다. 슬래시 베이스를 반영한다.
- **middle:** MIDI 48~59의 중간 성부. 낮은 음역은 최대 두 음이며 가까운 음을 밀집시키지 않는다. 기존 리듬을 담당한다.
- **upper:** MIDI 60~76. 리듬코드는 약하게 보강하고 미니코드는 기존 타격의 짧은 창 안에서 뒤따르는 오른손 화음과 기존 아르페지오를 사용한다.
- **transition:** 새 피아노 경과음을 추가하지 않는다. 기존 베이스의 approach/nextRoot 메타데이터는 가능한 경우 transition 역할로 표시한다.
- **표현:** 음별 duration/release/volume/commonTone 및 HOLD tie 가능 여부를 이벤트로 유지한다. 별도 페달 UI나 영구 페달 상태는 만들지 않는다.

화성은 기존 `getChordToneDescriptors`를 재사용한다. 구성음별 옥타브 후보를 열거하고 성부 이동 거리, 공통음, 교차/음역/밀집 조건으로 선택한다. 구성음을 임의로 7/9 화음으로 확장하거나 3도·7도를 빼지 않는다. 예를 들어 C의 G3–C4–E4가 Am의 A3–C4–E4로 이동하여 C4/E4를 유지한다.

미니코드 HOLD의 upper 공통음은 앞 음이 닿아 있고 실제 유한 샘플이 버틸 수 있을 때 재타격을 합친다. STAB과 아르페지오의 타격은 보존한다. 코드 변화, 쉼표, 기존 구간 경계 및 cycle 끝 전에 release까지 끝나도록 제한한다. 정지 시 기존 소스 종료와 함께 wet 출력을 감쇠하고 재시작 시 새 convolver로 교체하여 이전 반주의 잔향이 유입되지 않게 했다.

낮은 음에 필요한 최소 재생속도 0.125와 짧은 release는 새 기본 진행 이벤트에만 적용한다. 기존 사용자 진행의 재생속도/ADSR는 유지한다. 별도 샘플이나 새로운 합성 엔진을 추가하지 않았다.

## 사용자 진행 보호

리듬코드는 기본 라이브러리 ID와 원본 코드/박 길이가 모두 맞아야 적용한다. 미니코드는 코드에 포함된 기본 라이브러리 ID로 원본을 찾고 원본 slots/barCount가 일치해야 적용한다. 사용자 저장본의 ID 또는 편집으로 달라진 진행에는 적용하지 않는다. 기본 진행 판별값은 재생 세션에만 존재하고 세션 캐시 키에도 포함된다. 이조는 원본 검증 이후의 sounding chord에 적용한다.

## 검증

- 신규 테스트 8개 통과: C→Am 최소 이동, triad/maj7/add9/sus/7 구성음, 전체 기본 진행의 -12~+12 이조, 음역·성부 순서, 사용자 진행 보존, BPM 40/76/132/240에서 음 종료, HOLD tie, 실제 App 타임라인 및 Web Audio 소스 예약/정지 함수 실행.
- 실제 타임라인 통합 테스트에서 두 모드의 cycle 길이, 기존 피아노 타격 그룹, 기존 드럼/베이스 이벤트 보존 및 Cmaj7의 B 포함을 확인했다.
- 전체 `npm test`: **901개 중 885개 통과, 16개 실패**. 변경 전 `HEAD:src/App.jsx`를 주입한 대조 실행에서도 같은 기존 실패 16개가 재현됐다. 기존 UI/슈터/교재 관련 실패이며 신규 연주 테스트 실패는 없다.
- `npm run build`: 성공. 기존 대형 chunk 경고는 남아 있다.
- `git diff --check`: 통과.

브라우저에서 실제 스피커로 청음하거나 모바일 기기의 음질을 확인한 것은 아니다. 유한한 단일 피아노 샘플의 자연 감쇠는 유지하며, 무한 sustain이나 새로운 멀티샘플 음원으로 바꾸지 않았다. 미니코드의 기존 구간 레벨·마지막 HOLD는 재사용하고 새로운 인트로/종지 마디를 만들지 않았다.
