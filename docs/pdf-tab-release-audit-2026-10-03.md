# PDF → TAB 공개 전 오류 주입 검사

2026-10-03. 검사 범위는 제작실의 PDF 불러오기, TAB 변환, 취소, 검토, 기존 편집 보존, 브라우저 저장, PDF 출력이다. 앱 전체의 모든 기능이나 모든 휴대폰에서 무오류임을 뜻하지 않는다. 배포·커밋은 수행하지 않았다.

## 발견하여 수정한 문제

| 문제 | 재현 조건 | 수정 및 확인 |
|---|---|---|
| 가져오기 코드 로딩 실패가 편집기를 제거 | 편집 후 가져오기 모듈 요청 차단 | 편집 시작 전에 컨트롤러 코드를 준비한다. 엔진 자산 실패는 가져오기 창의 오류로 처리하며 편집기와 미저장 내용이 유지된다. 연결 복구 후 다시 분석할 수 있다. |
| 화면 변경으로 분석 결과 소실 | 분석 중 또는 완료 후 390px → 1440px | 작업 상태를 공통 컨트롤러에 두고 모바일·데스크톱 화면만 교체한다. 진행 중 작업과 완료 결과, 모달 상태가 유지된다. |
| PDF 초기화 중 취소해도 작업이 끝나지 않음 | PDF Worker 메시지 전달을 멈춘 뒤 취소 | 원시 Worker를 처음부터 소유하고 모든 PDF 비동기 단계에 취소·시간 제한을 적용한다. 취소 후 작업자 0개. |
| OCR 초기화 취소·파일 누락 시 작업자 누수 | OCR 초기화 정지, Worker 오류, WASM 로더 404 | 초기화가 끝나기 전부터 Worker를 소유한다. 실패·취소 시 즉시 종료하며 모든 대기 작업을 거절한다. |
| OCR 실행 중 고장 나면 무한 대기 | recognize 요청 직후 Worker 오류 주입 | 실행 중 오류·잘못된 메시지·시간 초과를 처리하고 오류 표시 및 재시도를 제공한다. |
| 읽지 못한 페이지가 요약에서 숨겨짐 | 정상 TAB + 빈 중간 페이지 + 정상 TAB | `pagesWithoutTab`에 페이지 번호를 보존하고 분석 결과와 편집기에 안내한다. 빈 표지인지 누락 악보인지는 원본 확인 대상으로 남긴다. |
| 회전된 숫자를 잘못된 현에 배치 | 네이티브 텍스트 PDF를 180도 회전 | 다수 숫자의 실제 화면 방향을 검사해 옆으로/거꾸로 놓인 경우 변환을 중단하고 방향 수정을 안내한다. 이미지 스캔 전체의 자동 방향 인식 기능은 아니다. |

OCR 클라이언트는 고정된 Tesseract.js 6.0.1 Worker 메시지 규약을 사용한다. 기존 `createWorker`는 초기화 완료 전 작업자 핸들을 주지 않아 실패 시 즉시 정리할 수 없었다. 라이브러리 업그레이드 시 실제 OCR 코퍼스와 작업자 수명 검사를 다시 실행해야 한다. PDF 출력·일반 PDF 뷰어의 작업자 소유 방식은 바꾸지 않았다.

## 새 검사 결과

- 엔진 경계·오류 주입 **29개 통과**: 빈/손상/암호화 PDF, 40MB 초과, 잘못된 확장자, 대문자 확장자, 20페이지 허용 및 21페이지 거부, 극단적인 페이지 크기, 오선보만 있는 PDF, 회전된 PDF, 누락 페이지, 단계별 취소, Worker 오류, 자산 404, 오프라인 첫 실행, CPU 6배 감속.
- 제작실 UI **8개 통과**: 코드 준비 상태, 네트워크 장애 후 복구, 분석 중/완료 후 화면 전환, 가로 568×320 화면, 열기 연속 클릭, 분석 취소 8회 후 재실행, 누락 페이지 안내.
- 저장·복구 **6개 통과**: 정상 저장, 실제 브라우저 저장 공간 소진, 미저장 편집 취소 후 재시도, 저장 권한 오류, 변환 결과 오류. 기존 악보 보존, JSON 파일 백업, 공간 확보 후 재저장, 중복 생성 방지를 확인했다. 이 검사는 저장 흐름을 분리하기 위해 기존 실제 분석 결과를 고정 입력으로 사용했다.
- 검사 종료 후 남아 있는 Worker는 모든 엔진 사례에서 **0개**였다. 실패가 예상되는 입력은 성공 변환이 아닌 오류 표시·자원 정리 여부로 판정했다.
- 동일 이미지 PDF **12회 연속 분석**: 매번 4마디·38개 프렛으로 동일했다. GC 이후 메인 스레드 JavaScript heap은 3회차 7,746,000 bytes → 12회차 8,041,544 bytes(약 0.28MiB 증가). 이 값은 브라우저 전체 메모리나 실제 휴대폰 RAM 측정이 아니다.
- **Chrome·Edge 배포용 빌드**에서 실제 이미지 PDF 변환 후 PDF 파일 다운로드까지 통과했다. 저장 파일은 1페이지, 금지 파일명 문자 치환, 원본 편집 데이터 보존을 확인했다. Poppler로 출력 PDF를 렌더링해 내용과 배치를 확인했다.
- 기존 모바일 320·390·440px 화면 검사와 별도로 짧은 가로 화면도 검사했다.
- 전체 단위 테스트 **1,725개 통과**, 빌드 및 개인 악보·오디오 배포 제외 검사 통과. 기존 큰 번들 경고는 남아 있다.

## 인식 정확도 회귀 검사

서로 다른 글꼴, 200/110/75dpi, 흐림, 잡음, 희미한 빔 등을 포함하는 독립 제작 PDF 26종을 새 작업자 경로로 전부 재실행했다. 정답은 인식기에 전달하지 않았다.

| 지표 | 결과 |
|---|---:|
| 정답 음/뮤트 | 1,014개 |
| 올바르게 입력 | 904개 |
| 확정 프렛 오입력 | 0개 |
| 누락 | 110개 |
| 인식 마디 | 104 / 104 |
| 리듬이 정확한 마디 | 100 / 104 |
| 숫자와 리듬이 모두 완전한 마디 | 53 / 104 |
| 이전 검증보다 나빠진 사례 | 0개 |

남은 리듬 오류 4개와 누락은 검토 대상이다. 이 수치는 합성 스트레스 자료에 대한 결과이며 일반 악보 전체의 정확도가 아니다. 검토가 필요하다는 표시가 모든 종류의 오인식을 반드시 잡는다는 보장도 없다.

## 공개 판단과 미검증 범위

현재 기능은 **6현 기타 TAB PDF에서 편집 가능한 초안을 만드는 기능**으로 안내해야 한다. 원본과 숫자·리듬·튜닝·카포를 비교해야 한다. 일반 오선보 PDF → TAB, 오선보에만 있는 리듬 가져오기, 4·5현 베이스 PDF 인식은 이 검사나 수정으로 추가되지 않았다.

실제 iPhone/Safari·Android 기기의 메모리 압박, OS 강제 종료, 통화 전환, 파일 공유 시트는 검사하지 못했다. 설치된 WebKit/Firefox 실행 파일이 없어 해당 엔진도 검증하지 않았다. CPU 감속·뷰포트 에뮬레이션은 물리 기기 검사를 대체하지 않는다. 첫 실행에 필요한 엔진 파일이 없는 오프라인 환경은 명확한 오류 후 온라인 재시도를 지원하며 완전한 오프라인 앱으로 주장하지 않는다.

발견한 안정성 오류의 재현 사례는 수정 후 통과했다. 그러나 남은 OCR 누락과 리듬 오류 때문에 무검토 자동 완성 기능으로 공개할 수준은 아니다.

## 재현 자료

결과는 Git에서 제외된 `artifacts/pdf-tab-release/`에 있다. `summary.json`, `before/engine.json`, `after/engine.json`, `orientation/engine.json`, `before/ui.json`, `final/ui.json`, `coverage/ui.json`, `desktop-save/results.json`, `memory/result.json`, `export-chrome/result.json`, `export-edge/result.json`, `corpus-comparison.json`을 참조한다. 개발 도구로만 사용하는 시험 PDF는 배포 자산에 포함하지 않는다.

필요 환경: 기존 TAB 코퍼스, ReportLab/pypdf, Chrome, Playwright, 5174 개발 서버. `PLAYWRIGHT_MODULE`에 설치된 Playwright 모듈 경로를 지정한다. PDF 출력 검사는 빌드 후 4174 preview 서버를 사용한다.

```powershell
python scripts/create-pdf-tab-boundaries.py
node scripts/verify-pdf-tab-release-engine.mjs after
node scripts/verify-pdf-tab-release-ui.mjs final
node scripts/verify-pdf-tab-release-memory.mjs
node scripts/verify-pdf-tab-corpus.mjs release
node scripts/verify-pdf-tab-release-export.mjs
node --test tests/pdf-tab-worker-lifecycle.test.mjs
npm test
npm run build
```
