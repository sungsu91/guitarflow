# 외부 악기 입력 확장

## 구현 범위

- MIDI 연결은 `src/input/midiInput.js`의 단일 관리자가 소유한다. 장치 선택을 화면 재진입 시 유지하고, 장치 ID·MIDI 채널(1–16)·음높이·velocity·시각을 포함한 이벤트를 현재 소비자 한 곳으로 전달한다.
- 악보는 기존 `midiStepInput`의 70ms 화음 묶음 및 선택 음길이 입력을 유지한다. 게임은 해당 묶음기를 사용하지 않고 새 Note On을 즉시 처리한다.
- 중복 Note On은 장치/채널/음높이별 눌림 상태로 억제한다. Note Off 또는 velocity 0 Note On 이후 재타격을 허용한다. 피치벤드/CC/서스테인은 무시한다. MIDI 채널로 줄을 추정하지 않는다.
- 게임은 음높이와 옥타브를 현재 표적과 비교한 뒤 기존 명중·발사 경로를 사용한다. 게임 시작 대기·일시정지·카운트인·모달에서는 명중하지 않는다. MIDI 선택 시 마이크를 새로 요청하지 않는다.
- 기본 마이크를 유지하며, 외부 입력은 정확한 deviceId를 요청한다. 제약 조건 재시도에서도 선택한 장치를 유지하고 다른 마이크로 자동 대체하지 않는다.
- 외부 입력의 실제 트랙 설정에 여러 채널이 있고 Web Audio 채널 분리가 가능할 때만 채널 선택을 표시한다. 채널 번호는 브라우저 채널 순서이며 인터페이스의 인쇄된 단자 번호와 같다는 보장은 없다.
- 입력 미터와 클리핑 표시는 선택한 입력 신호의 분석용 필터/게인 적용 전 PCM을 사용한다. ADC 내부 클리핑이나 장비 DSP 이전 신호를 측정하는 기능은 아니다.
- 연결 종료/장치 목록 변화, 권한 거부, 기타 연결 실패를 구분한다. 전면 복귀 및 장치 재연결 시 활성 소비자가 복구하며 수동으로 끈 마이크는 자동으로 켜지 않는다.
- 악보 편집 메뉴, 게임의 사운드 및 리듬 설정, 튜너의 튜닝 설정 안에서 '장치 연결'을 연다. 모바일/데스크톱은 별도 UI 컨테이너를 조건부 렌더링하며 연결 상태와 로직은 공유한다.

## 검증

- `npm test`: 기존 회귀 테스트와 새 MIDI/오디오 모의 테스트.
- `npm run build`: 프로덕션 빌드 및 배포 미디어 검사.
- `node scripts/verify-tuning-midi.mjs`: 모바일 360/390 및 데스크톱 1440, 테마·화음·커서·저장·다시 열기·권한·포트 교체.
- `node scripts/verify-external-input.mjs`: Chrome 모바일 크기 390/데스크톱 1440에서 모의 MIDI 게임 명중, 추가 마이크 요청 없음, USB 오디오/채널 선택, 레벨, 연결 해제/재연결, 권한 거부 후 재시도, MIDI 미지원 시 튜너 오디오 유지. 오디오는 Web Audio 합성 스트림이다.
- 새 테스트: `tests/external-midi-input.test.mjs`, `tests/external-audio-input.test.mjs`; 장치 재연결 테스트는 `tests/mic-foreground-recovery.test.mjs`에 추가했다.

## 이번 패치의 한계

- 일반 오디오 악보 입력, 다성 코드 인식, 실시간 리듬 채보는 구현하지 않았다.
- MIDI 피치벤드는 새 타격도 음높이 변경도 만들지 않는다. 현재 Note 번호 그대로 판정한다. MIDI 2.0 UMP, MPE 표현, 줄별 매핑, 벤드 범위 협상은 지원하지 않는다.
- 악보에 들어가는 같은 음높이의 화음은 기존대로 중복 제거한다. 장치/채널 정보는 공통 입력 이벤트에 보존하지만 기존 악보 문서에 연주 장치 메타데이터를 추가 저장하지 않는다.
- MIDI 포트 ID가 바뀌면 사용자가 다시 선택해야 한다. 오디오 장치 ID가 달라진 경우도 재선택한다. 선택은 현재 페이지 세션 내에서 공유한다.
- 기존 오디오 스튜디오 녹음은 이번 범위가 아니며, 그 별도 녹음 경로까지 통합한 것은 아니다.
- 실제 PC/Android USB 호스트·전원·드라이버, iPhone Safari의 외부 입력 노출/라우팅, 실제 채널 순서, MIDI 기타 메시지, 지연·피킹 강도·왜곡별 정확도는 장비로 검증해야 한다. Chrome의 모바일 크기 테스트는 Android/iOS 실기기 검증이 아니다.
