# 모바일 PDF 전체 화면 구성 (2026-09-15)

모바일 전용 HUD/연습 바를 분리하고 PdfPractice의 PDF 렌더러, 주석, 저장 큐, Undo/Redo, 마디 매핑, 메트로놈을 재사용했다. IndexedDB 데이터 구조는 변경하지 않았다.

- 상단: 뒤로가기 / 제목 / 작은 문서 메뉴 / 완료(보기 상태에서는 편집). 모바일 PDF가 열린 동안 보관함 탭과 홈/메뉴 행은 렌더링하지 않는다.
- 본문: 고정 화면의 남은 공간을 PDF에 할당하고 PDF 내부만 스크롤한다. 390×844에서 HUD 51px, PDF 영역 686px, 도구/연습 영역 107px. 기본 너비 맞춤과 기존 핀치를 유지한다.
- 하단: 이동·펜·텍스트·자르기·Undo·Redo 및 이전/시작/클릭 가능한 BPM/다음. 안전 영역 여백을 반영한다.
- 펜 설정과 자르기/마디 작업 버튼은 작은 오버레이로 표시해 본문 치수를 바꾸지 않는다. 완료된 텍스트 직접 드래그도 유지한다.
- 문서 메뉴: 마디 설정, 정보, 너비 맞춤, 자르기 초기화, 원본 보기, 전체화면, 연습 설정. 원본 보기는 주석/자르기/마디 오버레이를 잠시 숨기며 데이터와 원본 Blob을 수정하지 않는다.
- 모바일에서 처음 PDF를 열면 도구를 사용할 수 있는 상태로 열린다. 완료로 보기 상태를 전환하며, 데스크톱의 기존 편집 진입과 도구/설정 배치는 유지한다.

## 수정 파일

- src/pdf/MobilePdfChrome.jsx: 모바일 HUD, 문서 메뉴, BPM 팝오버와 하단 연습 바.
- src/pdf/mobilePdfChrome.css: 모바일 전체 높이, 고정 UI, 중립 버튼과 선택 색상.
- src/pdf/PdfPractice.jsx: 모바일/데스크톱 조건부 UI, 기존 동작 연결 및 원본 미리보기.
- src/pdf/PdfStudio.jsx: 모바일 PDF에서 보관함 전용 상단을 렌더링하지 않음.
- src/pdf/PdfAnnotationLayer.jsx: 모바일용 조밀한 툴바, 필요한 상태에서만 작은 문맥 오버레이.
- scripts/verify-pdf-mobile-chrome.mjs: 새로운 레이아웃의 브라우저 검증.

## 검증

Chrome 모바일 터치 에뮬레이션 360×800, 375×812, 390×844, 393×852, 430×932 및 데스크톱 1440×1000에서 펜·인라인 텍스트·자르기 입력, 도구 간 본문 치수 유지, Undo/Redo, 마디 매핑, 문서 메뉴, BPM 변경, 재생 시작/정지, 페이지 이동, 다시 열기, 가로 넘침 없음, JavaScript 예외 없음 확인.
390×844 추가 검증에서 연속 페이지 보기 전환, 핀치 후 원본 편집 데이터 유지, 너비 맞춤 복귀, 전체화면 닫기를 확인했다.
캡처: artifacts/pdf-mobile-chrome/390-pen.png, 390-text.png, 390-crop.png.

브라우저 에뮬레이션이며 실제 iPhone 키보드 및 하드웨어 검증은 아니다. PDF 페이지 종횡비를 유지하므로 짧은 페이지는 화면 하단에 보기 배경이 남을 수 있다.
