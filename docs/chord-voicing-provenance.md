# 신규 기타 voicing 출처 및 생성 방식 확인

결론: 신규 코드 전체가 검증된 기타 chord voicing 기준으로 만들어졌다고 승인할 수 없다.

범위: 신규 14타입 + 기존 공식의 운지를 보충한 6/9·m7b5 = 16타입, 31개 템플릿 전부.

## 실제 생성 방법

- additionalChords.js에 상대 fret/줄/손가락 tuple을 직접 작성했다. 외부 기타 코드 사전의 검증된 운지 목록을 가져온 구조는 아니다.
- grip()은 동일 fret·동일 손가락으로 적힌 점들을 묶어 바레를 만든다. 손가락을 적어 두고 바레를 만들었다는 사실은 실전성 검증이 아니다.
- 13/maj13/m13의 E형 6개는 하나의 thirteenth() 함수에서 3도/7도 fret를 바꾸고 5도 줄을 포함하거나 빼서 만든다. A형 13/m13은 별도 직접 작성 데이터다.
- buildChordTemplateCandidates()가 루트 줄에 맞춰 형태를 이동하고 이후 옥타브 후보를 생성한다. buildGeneratedChordShapeOption()은 각 줄/fret의 pitch를 계산한다.
- 실제 신규 선택 경로는 이 템플릿 이동 방식이다. buildCompactChordToneNotes()의 음별 지판 검색/분산 배치는 이 신규 타입들의 사용 경로가 아니다. 피아노 보이싱 데이터의 가져오기·변환 경로도 확인되지 않는다.
- 그러나 기타 줄/fret 튜플을 직접 만든 것만으로 정식 기타 voicing이라는 기준이 충족되지 않는다. 현재의 문제는 근거 없는 형태와 일반화된 이동을 기타용 데이터라는 이유로 승인한 데 있다.
- 1구간 선정에는 기존의 fret 기반 점수와 정렬이 사용된다. 출처 검증, 코드별 대표성 검수, 검증된 open/barre 우선 목록을 요구하는 관문이 없다.

## 출처와 검증의 구분

이전 문서의 두 교육 링크는 add2/add9 개념 및 13 계열 생략 관례의 참고 자료다. 이 자료를 위 31개 각각의 정확한 fret/운지/바레/이동 가능성과 대표성을 검증한 출처로 간주할 수 없다.

templateId는 내부 식별자다. 출판물·강사 시연·기타 코드 사전의 해당 항목으로 연결되는 출처 식별자가 아니다. Open/E/A/C/G/full/shell이라는 ID 또는 '정석'이라는 문자열도 검증 증거가 아니다.

일부 형태가 실제 흔히 쓰이는 형태와 일치할 수 있지만, 현재 개별 출처와 검수 기록만으로 전체를 일괄 승인할 수 없다. 반대로 출처가 없다는 사실만으로 모든 형태가 연주 불가능하다고 판정하지도 않는다.

## 적용해야 할 승인 기준

1. 화성이론의 전체 정의를 독립적으로 검증한다.
2. 정확한 기타 string/fret shape 및 손가락·바레·뮤트의 근거를 대조한다.
3. 개방현을 포함한 원형을 이동할 수 있는지 따로 확인한다. 원형 검증을 모든 조옮김의 검증으로 대신하지 않는다.
4. 실제 음과 필수음/허용 생략음을 대조한다.
5. 해당 코드의 대표 1구간으로 적절한지 별도로 확인한다.

이 기준은 향후 수정의 승인 조건이며, 이번 확인 작업에서 아직 구현하거나 운지를 교체하지 않았다. 기존 정상 코드와 앱 로직에는 변경을 가하지 않았다.
