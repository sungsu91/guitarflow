# 슈팅게임 촬영모드

촬영모드 버튼 → 전면 카메라·마이크 권한 → 구도 확인 → REC → ■ → 합성 영상 확인 → 영상 저장.

모바일 촬영 중에는 게임 패널의 내부 크기·맵·좌표를 그대로 유지하고 패널 전체를 같은 비율로 축소한다. 카메라에는 화면 높이의 31.5%를 고정 배정한다(기존 35%에서 10% 축소). 모바일 크기·높이 조절바는 제거했다. 기타·스킨·펫·라이프·HUD·내가 친 음 표시도 함께 축소한다. 화면을 자르거나 가로로 늘리지 않으므로 게임 양옆에 여백이 생긴다. 저장 영상도 게임 전체를 contain으로 배치하고 카메라와 같은 경계를 사용한다. 게임 하단을 잘라내던 기존 16% 리프트는 사용하지 않는다. 촬영 종료 시 게임 배율과 네비게이션을 복원한다. 데스크톱은 별도의 기존 이동·크기 조절 카메라 UI를 유지한다.

모바일 카메라는 `contain` 기준 1.6배를 사용하되 원본 좌우 끝이 잘리지 않도록 표시 폭을 카메라 영역 안으로 제한한다. 따라서 가로 원본은 영역 너비에 도달하면 더 확대하지 않는다. 세로 방향은 일부 잘릴 수 있다. 프리뷰와 저장 영상이 같은 `cameraContainRect`를 사용한다. 카메라 입력은 1280×720, 16:9를 선호하며 지원 환경에서는 resizeMode none으로 브라우저의 추가 크롭을 피하도록 요청한다. 이는 기기의 실제 화각 확장이나 가로 원본 제공을 보장하지 않는다. 별도 배율·높이 변경 UI는 없다. 저장 영상도 같은 게임/카메라 경계와 비율, 좌우 반전을 사용한다. 데스크톱 카메라는 기존 `cover` 방식을 유지한다. 결과 확인 영상은 하단 버튼 영역을 제외한 공간에 contain 방식으로 맞춰 전체가 보인다. 다시 촬영·저장·종료 버튼은 아래에 별도로 배치한다. 데스크톱 전용 카메라 레이아웃과 모바일 전용 레이아웃은 별도 컴포넌트이고 미디어 상태·저장 로직은 공유한다.

## 기존 게임 보호

- App에는 촬영 컴포넌트와 네비게이션·독립 음정 모니터의 조건부 렌더링만 연결한다.
- 촬영 중 게임 패널의 크기나 스타일을 변경하지 않는다. 게임 DOM을 다른 부모로 이동하거나 다시 마운트하지 않는다.
- 적·발사체·충돌·피치 판정·타이밍·난이도·점수 로직은 변경하지 않는다.
- 게임이 사용 중인 마이크의 오디오 트랙을 복제한다. 촬영 종료는 복제본만 정리하며 원래 게임 마이크를 종료하지 않는다. 마이크가 아직 없다면 기존 게임의 마이크 시작 경로를 이용한다.
- 게임 사운드는 공유 오디오 버스의 limiter에서 별도의 녹음 destination으로 병렬 연결한다. 마이크와 이 출력을 한 오디오 트랙으로 합친다. 병렬 연결에 실패하면 마이크만 녹음한다. 원래 출력 연결과 AudioContext는 종료하지 않는다.

## 영상 합성과 현재 제한

**현재 게임은 canvas가 아니라 DOM/CSS 렌더러다. 이 구현은 화면 녹화와 동일한 품질·프레임률을 보장하지 않는다.**

`sceneCapture.js`가 현재 게임 DOM의 위치·크기·변환을 읽어 전용 Canvas에 그린다. 이미지와 애니메이션 시트는 원본의 해당 프레임을 직접 사용한다. 글자·카운트다운·메뉴는 `canvasPaintTexture.js`가 실제 DOM의 글자 위치를 읽어 Canvas 텍스트·그라데이션·도형으로 직접 그린다. 아이콘은 HTML이 없는 독립 SVG로 그린다. iOS·Android·데스크톱이 같은 경로를 사용하며, 내용이 바뀔 때만 캐시를 갱신한다. HTML 전체를 매 프레임 복사하던 html2canvas 경로와 의존성은 제거했다. 게임과 카메라를 하나의 Canvas에 합성한 뒤 `captureStream(30)`과 MediaRecorder로 저장한다. 프리뷰에서는 캡처를 실행하지 않으며 모듈도 REC를 누를 때 지연 로드한다.

- 게임과 카메라는 직렬화된 하나의 루프에서 30fps를 목표로 갱신한다. 처리 시간이 길면 프레임을 누적하거나 중복 작업을 시작하지 않는다. 목표 30fps와 실제 녹화 프레임률은 다르며, 기기·맵·브라우저 부하에 따라 낮아질 수 있다.
- 글자·메뉴 캐시는 48MiB/128개를 기준으로 사용하지 않는 항목을 제거한다. 스프라이트 프레임은 32MiB 내에서 재사용한다. 원본 이미지와 사용 중인 항목, 인코더 메모리는 별도이므로 이 수치는 프로세스 전체 메모리 상한이 아니다. 배경 캐시 키에는 자식의 음 이름·점수 등을 넣지 않아 불필요한 배경 재생성을 막는다.
- 36프레임 펫 시트의 네 모서리, 독립 SVG의 위치, 숫자의 글자 그라데이션과 일시정지 메뉴를 검사한다. 기존 배경 클리핑 오류로 생기던 숫자 뒤 사각형, 펫 일부 잘림, SVG 위치·크기 오류를 수정했다.
- 실제 DOM에는 쓰지 않는다. 충돌·피치 판정·점수·적 속도는 기존 공용 로직을 계속 사용한다. 촬영으로 인한 스타일 읽기·그리기·인코딩 비용까지 없어지는 것은 아니다.
- 기타·몬스터 PNG/JPEG는 출력 크기로 한 번 축소한 뒤 재사용하고, 프레임 캐시에는 최근 사용 순서를 반영한다. App의 초기 설정·코드 진행·프리셋 읽기는 `useLazyRef`로 최초 한 번만 수행한다. 기존 ref의 변경 가능성과 저장된 초기값은 유지한다.
- CSS 3D 원근 변환, 배경 흐림(backdrop-filter), 마스크와 일부 혼합 효과는 원래 브라우저 합성 결과와 다를 수 있다. 모든 맵·스킨의 픽셀 일치는 보장하지 않는다. 특히 별도 WebGL 맵은 추가 검증이 필요하다.
- 브라우저 화면 공유를 요구하지 않는다. 모바일에서 정확한 화면을 실시간으로 캡처하는 범용 웹 API가 없으므로, 높은 프레임률과 모든 효과의 동일한 재현이 필수라면 공유 렌더러의 캡처 가능한 출력 설계 또는 네이티브 녹화 경로가 별도 작업으로 필요하다.
- 처음 REC를 누르면 카메라·이미지 준비를 기다린다. 준비가 완료되어 MediaRecorder가 시작된 시점부터 녹화 시간을 표시한다.
- 메모리 보호를 위해 10분 또는 수집된 영상 조각 200MiB에서 자동 중지하고 결과 확인 화면을 제공한다. 서버 업로드나 자동 사진 앱 저장은 없다.
- 게임 캡처 원본과 합성 영상은 모두 가로 1080px로 렌더링한다. CSS 화면 폭이 390px이어도 저해상도 캡처를 나중에 확대하지 않는다. 인코더 요청 비트레이트는 10Mbps이며 실제 값은 브라우저에 따라 달라질 수 있다. 모바일 390×844 검사에서 저장 영상은 1080×2340이었다.
- 녹화 시작 시 출력 화면 비율을 정한다. 녹화 도중 화면 크기를 바꾸더라도 저장 파일의 해상도는 유지된다.

## Safari / iPhone / PWA

HTTPS 또는 localhost에서 사용한다. 실제 API 존재 여부를 검사하고 MP4, WebM/VP8/Opus, WebM 순으로 지원 형식을 선택한다. 명시적 MIME 형식을 지원하지 않는 구현에서는 브라우저 기본 설정을 시도하고 실패하면 게임 화면으로 복귀한다.

MP4의 H.264 레벨은 브라우저가 해상도에 맞게 선택하도록 둔다. 세로 1080×2340에 맞지 않는 낮은 레벨을 고정 요청하지 않는다.

사용자가 영상 저장을 누르면 파일 공유 지원 환경에서는 시스템 공유창을 사용한다. 그렇지 않으면 다운로드 링크를 실행한다. 공유 취소 시 영상은 유지한다. 공유 기능이 노출되어 있지만 실제 공유가 실패하는 브라우저에서는 다운로드를 시도한다. 다운로드 요청 이후 OS에 실제로 파일이 저장되었는지는 웹 앱이 확정할 수 없으므로 UI도 저장 완료로 단정하지 않는다.

실제 iPhone 저장 파일에서 왼쪽 위 작은 화면과 잘못된 크기의 문자가 보고되었다. HTML을 SVG foreignObject로 변환하던 경로를 제거해 별도 HTML 문서의 레이아웃·배율 재계산에 의존하지 않도록 했다. 텍스트 위치는 원본 DOM Range에서 읽고 1080px Canvas에 직접 그린다. 일부 그림자·필터 효과는 원본과 다를 수 있다. 이 변경이 해당 iPhone 증상을 해소했는지는 배포 후 실기기 확인이 필요하다.

결과 재생 중에는 라이브 카메라 요소를 언마운트하고 srcObject를 분리한다. 재촬영 시 기존 카메라 스트림을 다시 연결한다. 녹화 합성에서도 촬영 UI·재생 UI·라이브 카메라 DOM은 제외한다. 카메라는 별도 합성 단계에서 한 번만 그린다.

`verify-shooter-recording-quality.mjs`는 foreignObject 직렬화를 금지한 상태에서 카운트다운·SVG·스프라이트 픽셀과 준비 취소를 검사한다. `verify-shooter-recording-browser.mjs`는 결과 확인 시 라이브 카메라 제거와 재촬영 시 연결 복원을 검사한다. 실제 iPhone/갤럭시 호환성 검증을 대신하지 않는다.

**iPhone 실기기 Safari와 설치형 PWA는 이 개발 환경에서 검증하지 못했다.** 아래 자동 검증은 Chromium과 합성 카메라·마이크를 사용했다. 실제 iPhone에서는 카메라·기타 입력 동시 사용, 오디오 믹스, 잠금·전화 수신, 시스템 공유창에서 사진/파일 저장, 긴 영상의 메모리 사용량을 추가 확인해야 한다. 이 기록을 실기기 호환성 보증으로 해석하면 안 된다.

## 정리와 오류 복귀

카메라·마이크 거부, 미지원, 프리뷰 오류, 준비 시간 초과, 녹화 오류, 빈 결과, Blob URL 생성 실패, 장치 연결 종료, 페이지 전환 시 촬영 자원을 해제하고 원래 레이아웃으로 복귀한다. 늦게 완료되는 권한 요청에도 세대 번호를 확인해 반환된 스트림을 즉시 종료한다.

정리 대상은 MediaRecorder 이벤트, 촬영용 트랙, 오디오 병렬 연결, 합성 스트림, 진행 중인 이미지 요청, 텍스처·프레임 캐시, 타이머, animation frame, Object URL이다. 결과 확인 중 공유창 취소·일시적 백그라운드 진입은 결과를 삭제하지 않는다. 저장 실패도 결과를 유지해 재시도할 수 있게 한다.

## 검증

- `npm run build`: 성공. 기존 큰 번들에 대한 Vite 경고는 남아 있다.
- 촬영·충돌·게임 규칙·피치 판정 관련 선택 테스트 28개 통과.
- `scripts/verify-shooter-recording-browser.mjs`: 모바일 390×844 및 데스크톱 1366×768에서 실제 MediaRecorder 파일 생성·디코딩·다운로드, 오디오/비디오 트랙, 재촬영·URL 해제, 게임 내부 크기·네비게이션 복원, 촬영 트랙 종료와 게임 마이크 유지 확인.
- 카메라 거부, 마이크 거부, MediaRecorder 미지원, 생성자 오류, 늦은 권한 응답, 화면 전환, 녹화 오류, 카메라 연결 종료, 빈 결과, URL 생성 실패도 검사한다.
- 8초 녹화 파일의 1·2·3초 프레임을 실제로 디코딩해 게임 영역의 변화와 1080px 출력 크기를 검사한다. 플레이어 로딩 아이콘이 섞이지 않도록 영상 프레임 자체를 추출한다.
- `scripts/verify-shooter-recording-quality.mjs`: 실제 카운트다운·일시정지·펫의 원본/녹화 이미지, 플레이 중 그리기 시간과 RAF 빈도, 36프레임 시트의 픽셀과 SVG 위치, 준비 중 취소를 검사한다. 결과의 `frames`는 5초간 호출된 게임 캡처 횟수이고 `renderP50/P95`는 그리기 호출 시간(ms)이다. GPU 완료 시간이나 저장된 영상의 FPS를 뜻하지 않는다. RAF 횟수도 브라우저가 실제로 화면에 표시한 프레임 수와 동일하지 않다.
- `scripts/inspect-recording-mp4.mjs`는 Chromium MediaRecorder가 만든 fragmented MP4의 영상 샘플 간격을 읽는다. 2026-09-09 배포용 빌드, PC Chrome/RTX 3060, 가상 카메라·마이크의 8초 검사에서 Canvas UI 합성 변경 후 모바일 화면 1080×2340은 28.7fps(95% 프레임 간격 42.3ms), 데스크톱 화면은 28.6fps였다. `artifacts/shooter-recording/canvas-ui-production`에 파일과 검증 결과를 남겼다. 실기기·장시간 녹화 성능의 보증 수치가 아니다.
- 같은 PC의 개발 서버 검사에서는 약 16fps가 관찰됐고, CPU 프로파일에서 React 개발용 JSX 처리가 큰 비중을 차지했다. 실사용 성능 검사는 `npm run build` 후 `npm run preview`로 실행하는 배포용 코드에서도 진행한다. 개발 서버와 배포용 빌드의 수치를 최적화 전후 수치로 비교하지 않는다.

QA 스크립트에는 별도의 Playwright 설치가 필요하다. `PLAYWRIGHT_MODULE`에 기존 Playwright 모듈의 file URL, `CHROME_PATH`에 브라우저 경로, `RECORDING_TEST_URL`에 로컬 서버 주소를 지정할 수 있다. 결과는 `artifacts/shooter-recording/verification.json` 및 해당 디렉터리의 이미지·영상에 저장된다. 이 샘플의 녹색 카메라는 자동 검사용 가상 장치다.


## 앱 전환 후 복귀

슈팅 모드에서 앱을 벗어나면 플레이를 일시정지한다. 복귀·pageshow·focus에서 마이크 상태를 확인하고 interrupted/suspended AudioContext를 재개한다. 종료된 입력 트랙 또는 닫힌 컨텍스트는 기존 startMic 경로로 재연결한다. 자동 재개가 거절되면 다음 pointerdown/keydown에서 재시도하며, 꺼진 마이크를 임의로 켜지 않는다. 복귀 후 400ms 동안 오디오 시간이 멈춰 있거나 입력 트랙이 계속 muted이면 재연결한다. 기타를 치지 않는 조용한 구간은 연결 끊김으로 판단하지 않는다. 실제 기기별 동작은 별도 확인이 필요하다.

녹화 중 visibilitychange(hidden)·pagehide 또는 트랙 종료를 받으면 중지하고 그때까지의 Blob을 결과 화면에 남긴다. 연속 이벤트로 중지를 중복 요청하거나 결과를 삭제하지 않는다. 준비·프리뷰 상태의 앱 전환은 촬영모드를 종료한다. 탭 종료/프로세스 강제 종료에서 메모리의 파일 보존이나 백그라운드 연속 녹화를 보장하지 않는다. 실제 저장은 사용자가 결과 화면에서 진행한다.

`tests/mic-foreground-recovery.test.mjs`는 재개 거절 후 터치 재시도, 단일 재연결, 마이크 OFF 유지 및 이벤트 해제를 검사한다. 브라우저 QA는 visibilitychange와 pagehide를 연속 전달하고 실제 MediaRecorder 결과 Blob의 유지·재생을 확인한다. 시뮬레이션이며 iPhone·Galaxy 실기기 백그라운드 검증은 아니다.


## 녹화 전 넓게 찍기

모바일 프리뷰의 카메라 왼쪽에 대각선 화살표 버튼을 제공한다. REC·종료는 오른쪽 조작부에 유지한다. 기본 구도는 기존 1.6배 기준이며 넓게 찍기를 누르면 앱 확대를 해제해 원본 전체를 담는다. 브라우저가 실제 zoom 범위와 현재 배율을 제공하고 현재보다 작은 최소 배율이 있으면 applyConstraints로 적용한다. 되돌리면 진입 시 하드웨어 줌과 기본 표시 구도를 복원한다. 하드웨어 줌을 조절하지 못하면 원본 구도만 표시한다. 구도 버튼은 화살표 아이콘만 사용하고 미지원 설명 문구는 표시하지 않는다. Apple 기본 카메라와 같은 화각을 보장하지 않는다.

구도 변경 중에는 REC를 비활성화하고 녹화 중에는 구도 버튼을 렌더링하지 않는다. 재촬영에서는 선택한 구도를 유지하며 촬영모드를 새로 켜면 기본 구도로 초기화한다. 변경 요청 실패·종료된 세션의 늦은 응답은 기존 구도를 덮어쓰지 않는다. 녹화 합성도 프리뷰와 같은 구도를 사용한다.

모바일 카메라 조작부에는 REC/녹화 중지와 별도로 하단 종료 버튼을 제공한다. 기존 상단 촬영 종료와 같은 방식으로 촬영 자원을 해제하고 게임 화면으로 돌아간다.


2026-09-09 구도 전환 보정: 넓게 찍기는 실제 하드웨어 줌 변경을 확인한 경우에만 선택 상태를 바꾼다. 미지원이면 표시 확대를 풀거나 성공 상태로 바꾸지 않는다. 기존 표시 배율은 유지한다. 브라우저가 요청과 다른 줌을 적용하면 이전 값 복원을 시도한다.

모바일 슈팅·튜너 모드에서는 메뉴의 문의하기 바로 위에 새로고침을 제공한다. location.reload로 현재 주소를 다시 불러오며 플레이·카운트다운·촬영 중에는 비활성화한다. 저장된 설정을 지우지 않고, 서버의 배포 완료를 대신하지 않으며 캐시 무시를 보장하지 않는다.


모바일 슈팅·튜너의 화면 맨 위에서 비조작 영역을 아래로 130px 이상, 250ms 이상 당겼다 놓으면 새로고침한다. HUD를 포함한 main 화면이 손가락 이동의 45%만큼 내려오며 놓으면 원래 위치로 돌아간다. 짧은 당김·가로 드래그·멀티터치·touchcancel은 새로고침하지 않는다. 버튼·입력창·펫·기타 조작, 스크롤 중인 패널, 메뉴·도움말·에디터, 잠긴 화면, 슈팅 플레이·카운트다운·촬영 중에는 적용하지 않는다. 데스크톱 UI에는 추가하지 않는다. `scripts/verify-mobile-refresh.mjs`에서 Chromium 터치 입력으로 슈팅·튜너 양쪽의 메뉴 위치, 실제 reload, 짧은 당김 취소, 긴 당김 reload를 검사한다. 실제 iOS PWA 제스처는 별도 확인이 필요하다.


## 카메라 필터

모바일 카메라에서 좌우로 45px 이상 스와이프하면 원본·따뜻하게·차갑게·흑백 필터를 순환한다. 반대 방향은 이전 필터이며 세로 움직임·멀티터치·취소·버튼에서 시작한 동작은 변경하지 않는다. 키보드로 카메라 영역에 초점을 맞춘 경우 좌우 방향키도 지원한다. 프리뷰와 녹화 중 적용하며 재촬영에는 유지하고 촬영모드 재진입 시 원본으로 초기화한다.

필터 정의는 recordingMedia.js에서 공유한다. 프리뷰는 카메라 이미지 위 색상 합성 레이어로, 저장은 같은 색상과 합성 모드의 Canvas 레이어로 처리한다. 게임·여백·조작 버튼에는 적용하지 않는다. 매 프레임 픽셀 읽기나 HTML 캡처를 추가하지 않는다. Safari Canvas filter 속성에 의존하지 않는다. 브라우저 QA는 좌우 터치 순환과 저장된 MP4 카메라 픽셀의 흑백 적용을 검사한다.

## 피부·윤곽 보정

캠 왼쪽의 보정 버튼은 끔 → 자연 → 부드럽게로 순환한다. 기본은 끔이며 재촬영에는 유지하고 촬영모드 재진입 시 초기화한다. 모바일은 넓게 찍기 아래, 데스크톱은 이동 손잡이 아래에 배치한다. 미리보기와 저장은 cameraBeauty.js의 동일 GPU 출력과 프레임 캐시를 사용하며 기존 색감 필터를 그 위에 합성한다. 피부색 범위에서 경계를 보존하는 약한 평활화와 밝기 보정을 적용한다. 정밀 피부 분할이 아니므로 비슷한 색상의 물체에도 약하게 적용될 수 있다.

윤곽은 MediaPipe Face Landmarker가 찾은 볼·턱 4지점만 국소적으로 안쪽으로 당긴다. 얼굴 인식은 320px 이하 입력으로 별도 Worker에서 최대 6fps, 한 번에 1프레임만 처리하며 느리면 주기를 낮춘다. 얼굴을 놓치거나 결과가 처리 주기에 따른 417~583ms 넘게 오래되면 변형을 없앤다. 얼굴 인식 미지원·실패 시 피부 보정만 유지하며 WebGL 보정 자체가 불가능하면 원본을 유지한다. 켜져 있을 때만 모델을 내려받고 모든 영상 처리는 기기 안에서 수행한다. 카메라 영상은 서버로 전송하지 않는다. 윤곽 주변의 좁은 배경 영역도 국소 변형의 영향을 받을 수 있다.

public/vendor/face-landmarker에는 @mediapipe/tasks-vision 0.10.32의 WASM/JS와 공식 float16 v1 모델을 포함했다. vision_bundle.js는 npm 패키지의 vision_bundle.cjs를 내용 변경 없이 복사한 파일이다. 라이브러리 업데이트 시 패키지와 vendor 파일을 함께 갱신한다. 라이선스는 해당 폴더의 LICENSE/NOTICE.txt에 있다.

검증: tests/face-shape.test.mjs는 변형 방향·범위와 잘못된 인식을 검사하고, scripts/verify-camera-beauty.mjs는 실제 WebGL 결과의 피부 질감 감소, 비피부 색과 상하 방향 보존을 검사한다. RECORDING_TEST_BEAUTY=1로 녹화 브라우저 QA를 실행하면 보정 상태의 1080px MP4 저장·재생·중단·정리를 확인한다. 실제 iPhone/Galaxy 장시간 발열 및 프레임률은 기기 검증이 필요하다.

화각 버튼은 미리보기 진입 전에 실제 줌 축소와 원래 줌 복귀를 모두 확인한 기기에서만 표시한다. 줌 미지원·변경 무시·복귀 실패 시 렌더링하지 않으며, 이후 누를 때 기기가 변경을 거부하면 버튼을 제거한다. 원래부터 가장 넓은 줌이면 버튼을 표시하지 않는다.

## 움직임 왜곡 수정

실기기에서 얼굴 움직임에 따른 윤곽 왜곡이 보고되어 기하 변형(갸름하게·비대칭 교정)을 비활성화했다. 모든 단계에서 텍스처 좌표를 원본 그대로 사용한다. 보정 단계는 끔·자연·뽀샤시이며 피부 평활화·밝기와 얼굴 인식 기반 눈 아래 그림자 완화만 적용한다. 비대칭 교정을 제공한다고 표시하지 않는다. 위 윤곽 구현 설명은 이전 구현 기록이다.
