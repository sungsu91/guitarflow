# PDF 마디 수·여백 제거 (2026-09-15)

## 변경

- 마디 수는 `이 줄의 마디 수 [1][2][3][4] ×`로 표시한다. 숫자를 누르면 즉시 적용하고 닫는다. 모바일은 기존 안내줄에, 데스크톱은 작은 한 줄 팝업에 배치한다. 5~16마디 목록과 숫자 조절기는 제거했다. 기존에 저장한 마디 데이터는 유지한다.
- 기존 두 번 클릭과 같은 줄 높이 보정, 마디 분할/저장 경로를 재사용한다. 숫자 변경은 미리보기만 변경하며 PDF 캔버스를 다시 렌더링하지 않는다.
- 여백 자르기는 선택한 가장자리 띠를 **제거**한다. 두 점으로 선택 후 제거될 전체 띠를 붉은 사선으로 미리 표시하고 방향을 안내한다. 적용/취소를 명시적으로 선택한다.
- 화면 가장자리 3% 이내를 접점으로 인정한다. 모서리에서 두 방향이 가능하면 더 얇은 띠를 제안하며 실제 제거 범위를 표시한다. 가운데 영역이나 전체 페이지 제거는 거부한다. 한 번에 한 가장자리, 여러 번 적용하여 네 방향을 누적할 수 있다.
- 적용하면 남은 영역을 너비에 맞추며, 제거한 공간은 캔버스 크기와 PDF 렌더링 원점에서 제외한다. 흰색 가림막을 덧대는 방식이 아니다.

## 데이터와 재사용

- 기존 IndexedDB `scores.pageEdits[page]`에 `margins: {top,right,bottom,left}`를 저장한다. 값은 원본 페이지 비율이다. PDF Blob은 변경하지 않는다.
- 기존 `crop`(남길 사각형) 레코드는 그대로 지원한다. 새 편집 시 기존 crop을 누적 여백으로 변환하고 `crop:null`로 저장한다. 백업 정규화도 margins를 보존한다. DB 스키마 버전/원본 Blob 저장 방식 변경 없음.
- `pageCrop()`을 단일/연속 페이지 렌더러가 공유한다. 마디/메모는 기존 원본 좌표를 유지하고 표시 시에만 투영한다.
- 기존 annotation history 및 저장 큐를 사용하여 실행 취소/다시 실행, 저장 오류 처리, 보관함 재열기, 백업을 유지한다. 여백 초기화는 해당 페이지의 crop/margins만 해제한다.
