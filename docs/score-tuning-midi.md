# 악보 편집기 튜닝·카포·MIDI 단계 입력

## 적용 위치와 공용 코드

- `ScoreEditor.jsx`: 내 악보의 새 악보 생성·저장 악보 편집(`PdfStudio`)과 에튀드 편집(`EtudeStudio`)이 같은 컴포넌트를 사용한다. 각 호출자의 document, ID, 저장 콜백을 유지한다. PDF·이미지 뷰어에는 MIDI 입력을 연결하지 않는다.
- `EditorSettings.jsx`, `editorSettings.css`: 튜닝/카포/편집 공용 앵커 팝오버. 편집 메뉴에 기존 줄 배치, 자동 TAB, MIDI 상태/연결/장치 선택을 묶는다. 기존 테마 변수를 사용한다.
- `scoreTuning.js`: 현별 개방음, 카포, 실제 음높이, 운지 후보, 튜닝 변경, 자동 TAB 배치와 저장 필드 정규화.
- `enterMidiNotes.js`, `midiStepInput.js`, `useMidiKeyboard.js`: MIDI 메시지·연결 수명과 단계 입력. 기존 `inputRhythm`, `nextEntry`, 실행 취소 스택을 재사용한다.
- `scoreModel.js`, `editorCommands.js`, `convertScoreInstrument.js`, `useScorePreview.js`: 오선보/재생/직접 편집/악기 변환에서 카포를 한 번만 적용한다.
- `EditorScore.jsx`, `Score.jsx`, `scoreMetadata.js`, `printScore.js`: 미배치 TAB의 `?`, 튜닝·카포 표기, 매우 낮은 MIDI 음의 보표 간격과 인쇄.
- `EditorAudioDock.jsx`, `ScorePlayback.jsx`, `MobileScoreInput.jsx`: 모바일에서 재생 → BPM → 박자 소리 → 악보 소리 → 음색 선택을 한 행으로 렌더링한다. 데스크톱 음색 UI는 기존 배치를 유지한다. 비어 있는 피드백 행은 생성하지 않는다.

## 데이터와 입력 규칙

문서의 `capo`(없음=0), `autoTab`(`mode`, 상대 프렛 `min`/`max`), 기존 `instrument`/`tuning`을 저장한다. 음표는 `midi`, `string`, `fret`, `locked`를 갖는다. 기존 문서의 MIDI 값은 기존 현·프렛으로 계산하고, 누락된 카포는 0, 기존 운지는 직접 지정으로 해석한다.

기타 6현, 베이스 4현, 우쿨렐레 4현 프로필을 재사용한다. 표준·반음 다운·온음 다운을 제공하며 기타에 Drop D를 제공한다. 사용자 지정은 각 현의 실제 개방음과 옥타브를 표시한다. 프렛 상한은 기존 편집기의 지원 범위인 24를 유지하며, 카포 + 상대 프렛이 이를 넘지 않도록 검사한다. 실제 악기의 제작 사양을 탐지하는 기능은 아니다.

실제 일반음 = 현의 개방 MIDI + 카포 + 상대 프렛. 기존 자연 하모닉스는 원래의 하모닉스 간격 계산을 유지한다. 기타/베이스의 오선보 옥타브 이조는 렌더러에서 별도로 적용한다. VexFlow의 조표·마디별 임시표 상태 처리를 유지하며 플랫 단조의 반음 표기도 보완했다.

빈 악보에는 즉시 적용한다. 음표가 있으면 기본값인 음높이 유지 또는 운지 유지를 선택하고 취소할 수 있다. 전체 변경은 한 번의 실행 취소 단위다. 음높이 유지와 직접 지정 운지가 충돌하면 원래 MIDI와 `previousFingering`을 보존하고 `unplaced`로 표시한다. 편집 메뉴에서 사용자가 새 현·프렛을 확정할 수 있다. 충돌 상태에서 다시 튜닝하거나 MIDI 음을 추가해도 잠금을 자동 해제하지 않는다.

자동 배치는 현재 입력 화음과 앞뒤 이벤트를 대상으로 한다. 같은 현의 중복 배치를 금지하고, 누르는 프렛의 폭과 서로 다른 프렛 수를 제한한다. 선호 범위 안의 해를 우선하며 불가피하게 범위를 벗어나면 표시한다. 해가 없으면 원래 음높이를 남기고 `?`로 표시한다. 손 모양의 완전한 생체역학 모델은 아니며 사용자가 운지를 확정·수정할 수 있다.

MIDI 화음은 첫 Note On부터 70ms 이내 겹친 음으로 정의한다. 구성음 하나를 떼면 즉시 묶음을 확정한다. 70ms가 지난 입력은 타이머가 지연되어도 다음 단계로 분리한다. 계속 누른 건반의 중복 Note On을 무시하며 Note Off/velocity 0을 동일하게 처리한다. 서스테인은 음길이와 커서에 영향을 주지 않는다. 화음은 선택한 길이로 한 번만 커서를 이동한다. MIDI 실제 음높이에 튜닝·카포를 더하지 않는다.

이 경계 안에서 겹친 빠른 레가토는 정의상 화음이고, 70ms보다 넓게 펼친 화음은 다음 단계가 된다. 이는 악보 단계 입력의 명시적 묶음 규칙이며 실시간 리듬 인식/녹음이 아니다.

## 연결과 권한

연결 버튼을 눌렀을 때 최초 권한을 요청한다. 진입 시 Permissions API가 `granted`를 반환한 경우에만 자동 연결한다. 조회 API가 없거나 예외가 발생하면 자동 요청하지 않는다. 권한 로컬 저장 플래그는 없다. 요청은 `{sysex:false}`이고 마이크·카메라를 사용하지 않는다. 거부 후 반복 요청을 막고 사이트 권한 변경/재시도를 안내한다.

활성 편집기의 악보 입력 영역에 포커스가 있고 유효한 커서가 있을 때만 입력한다. 팝오버·설정·제목 입력·재생 및 재생 준비 중에는 입력하지 않는다. 화음 대기 중 커서나 포커스가 바뀌면 해당 대기 입력을 버린다. 언마운트/장치 변경 때 메시지 리스너와 타이머를 정리한다.

API 확인 기준: [Web MIDI 규격](https://www.w3.org/TR/webmidi/), [MDN Web MIDI API](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API).

## 검증

- `npm test`: 기존 테스트와 새 전용 테스트를 포함해 1,057개 통과.
- `npm run build`: 성공. 기존 대형 번들 경고는 남아 있다.
- `tests/score-tuning-midi.test.mjs`: 튜닝별 개방음, 카포 F♯4/G4/G♯4, 프렛 상한, 기존 문서 호환, 두 변경 방식, 잠금 보존, 화음 배치, 배치 불가·저장·삭제, 선호 범위, 점음표·셋잇단·쉼표·마디 경계, 악기 변환, MIDI 묶음·반복·페달·포커스/커서 변경을 검증한다.
- `scripts/verify-tuning-midi.mjs`: Headless Chrome에서 360×800/390×844 모바일, 1440×900/1440×1000 데스크톱, 844×390 회전, 화이트·다크 테마를 확인한다. 팝오버 열기 시 악보 위치 불변, 두 자리 프렛, 변경 모드와 실행 취소/다시 실행, MIDI 단음/화음/빠른 반복/길게 누르기, 입력 차단, 장치 선택/분리/재연결, 저장 후 재진입, 중복 등록 방지, 인쇄 미리보기 카포 정보, 사용자 지정 튜닝, 선호 범위, 미배치 음의 렌더링을 검증한다.
- 권한 시뮬레이션: 최초 요청, 사전 허용 자동 연결, 사전 거부, 실제 요청 Promise 거부, 조회 API 예외, Web MIDI 미지원. 거부 상태 재클릭 시 요청 횟수가 늘지 않음을 확인한다.

실제 MIDI 장치, 실제 브라우저 권한 팝업, 실물 모바일 기기에서의 검증은 수행하지 않았다. MIDI 메시지/장치/권한은 브라우저 API 대체 객체로 시뮬레이션했다. 화면과 실제 편집·저장·재생·인쇄 경로는 브라우저에서 실행했다.
