## 실제 크기

앱 바깥 10px와 내부 16px가 중복되던 좌우 여백을 16px로 수정했다. 루트의 zoom은 1, transform은 none이었다. 화면 전체 배율 변경 없이 역할별 크기를 적용했다.

| 요소 | 글자 크기 / 굵기 | 높이 |
| --- | --- | --- |
| 브랜드 | 18px / 700 | HUD 46px |
| 메뉴 | 16px / 500 | 터치 영역 44px |
| 탭 | 19px / 활성 700, 비활성 500 | 48px |
| 추가 버튼 | 15px / 500 | 46px |
| 검색 / 정렬 | 14px / 400, 15px / 500 | 모두 46px |
| 필터 | 16px / 활성 700, 비활성 400 | 40px |
| 섹션 제목 | 19px / 700 | 폴더 제목 영역 36px |
| 폴더명 / 개수 | 18px / 500, 14px / 400 | 68px |
| 악보명 / 보조 정보 | 18px / 600, 13px / 400 | 76px |
| 백업 | 17px / 500 | 64px |

390×844에서 콘텐츠 너비는 358px다. 상단 HUD y=8, 탭 y=62, 추가 버튼 y=126, 검색 y=188, 필터 y=246, 폴더 목록 y=342, 악보 목록 y=529, 백업 y=773이다. 폴더 2개와 악보 3개를 표시한 백업 행의 하단은 837px다. 데이터가 많거나 800/812px 높이에서는 자연스럽게 세로 스크롤한다.

## 시각 비교와 수정

첫 비교 후 검색과 정렬이 공통 CSS 우선순위 때문에 44px/46px로 달랐던 문제를 수정해 46px로 통일했다. 음표 아이콘은 목표의 연결된 두 음표 형태로 수정했다. 하단 안전 영역을 유지했다.

- `artifacts/library-visual/comparison.png`: 제공된 수정 전 화면 / 목표의 앱 내부 / 실제 수정 후.
- `artifacts/library-visual/after.png`: 실제 390×844 브라우저 캡처.
- `artifacts/library-visual/overlay.png`: 목표와 수정 후 50% 오버레이.
- `artifacts/library-visual/metrics.json`: 실제 DOM 좌표 및 계산된 글자 크기.

목표에서 휴대폰 외곽과 상태 표시줄을 제외한 영역을 너비 390px로 비례 조정했다. 제공된 수정 전 화면은 저장 데이터 수가 다르므로 전체 픽셀 차이를 일치율로 보고하지 않는다. 목표는 래스터 목업이며 동일한 글꼴 파일이 제공되지 않았다. Windows Chrome의 한글은 Malgun Gothic으로 표시되어 글자 형태가 완전히 같지 않다. 목표를 너비로 정규화한 행보다 명세의 최소 행 높이(폴더 68px, 악보 76px)가 크므로 하단 위치에도 차이가 남는다. 99.999% 일치를 달성했다고 주장하지 않는다.
