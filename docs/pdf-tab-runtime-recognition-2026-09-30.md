# PDF TAB 즉석 인식과 반복 운지 개선

검증일: 2026-09-30. 비교 기준: cf3dcd2c의 인식기와 `artifacts/pdf-tab-next/final` 결과. 실제 PDF는 사용자가 지정한 Desktop/sheet music에서 읽었다. 곡별 정답이나 파일 이름에 따른 분기는 인식 코드에 넣지 않았다. 수기 정답은 검증 스크립트에서만 사용하며, 앱은 가져온 PDF의 텍스트·픽셀을 그때 분석한다.

## 변경 내용

- 이미지 TAB의 줄기 조각, 동시 운지 사이 연결선, 아르페지오 선을 숫자 후보에서 제외한다. 제목·코드표·QR 대신 감지된 여섯 줄 내부를 검사한다.
- 얇고 작은 숫자는 작은 크기와 다른 문자 분할 방식으로도 읽는다. 최대 일곱 조건 중 서로 동의하는 읽기가 있어야 확정하며, 강한 충돌은 그대로 검토 대상으로 남긴다.
- 확대본에 일부 마디나 TAB 줄이 누락되어도 위치와 양쪽 마디 경계가 일대일로 일치하는 구간은 보완에 사용한다. 음표 목록을 합치지 않으며 원본 페이지·마디 수와 이미 읽힌 음을 보존한다.
- `X/x`를 현별 뮤트로 가져온다. 개방현 0과 구분해 저장한다.
- 이미지 안의 명시적인 반복 슬래시를 인식한다. 확인된 동일 운지는 제작실에서 자동으로 숫자를 생략하고 리듬 슬래시로 표시한다. 첫 운지와 바뀐 운지는 보이며, 쉼표·뮤트·미확정 운지 뒤로 임의의 코드를 이어 붙이지 않는다.
- 생략한 음도 문서에 남는다. 오선보와 재생은 실제 현·프렛 데이터로 생성한다. 2박마다 운지가 바뀌는 `4분–8분–16분–16분` 패턴을 검증했다.
- 인식 기능과 데이터 처리는 공유한다. 데스크톱 PDF 가져오기와 모바일 UI 분리를 유지한다.

## 원본 대조 결과

### Flower Dance: 선택한 10마디

1·2·3·4·13·15·16·44·45·46마디를 수기로 읽어 검사했다. 한 자리/두 자리 프렛, X 뮤트, 8분/16분 리듬을 포함한다. **전곡 정확도가 아닌 이 10마디의 결과**다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 정확히 입력한 운지·뮤트 / 151개 | 110 | 146 |
| 미입력 | 41 | 5 |
| 틀리게 확정한 운지 | 1 | 0 |
| 실제 음표 열의 리듬 일치 / 10마디 | 10 | 10 |
| 운지·리듬 모두 일치 / 10마디 | 4 | 7 |

변경 전에는 아르페지오 선이 가짜 프렛 1 열로 추가됐다. 해당 열은 별도로 오입력에 포함했으며 리듬 대조에서는 실제 음표 열과 분리했다. 변경 후 X 8개 중 7개를 정확히 읽었다. 남은 다섯 항목은 13마디 첫 이벤트 2번줄 0, 15마디 첫 이벤트 3번줄 9/6번줄 8, 16마디 일곱째 이벤트 2번줄 9 및 열째 이벤트 2번줄 X다.

전체 파일에서는 3페이지 63마디를 유지하고 입력된 운지·뮤트가 732개에서 845개로 늘었다. 검토 마디는 56개에서 37개로 줄었다. 입력 개수 증가는 전곡 정답률이 아니다.

### 독립 작곡 원본: A Little Further 전체 40마디

인식기에 전달하지 않은 작곡 원본 508개 운지와 비교했다. 정확한 운지 441→467개, 미입력 67→41개, 잘못 확정한 운지 0개다. 쉼표를 포함한 40마디 전체 리듬은 그대로 일치했고, 운지까지 완전한 마디는 11→19개다.

## 최종 검증

전체 단위 테스트 **1,569개 통과**. 배포 빌드와 개인 악보·음원 배포 제외 검사 통과. 기존 대형 청크·혼합 동적 import 빌드 경고는 남는다.

실제 PDF 다섯 개에 여섯 조건씩 **30회 기능 검사 모두 통과**했다. 매번 파일 이름을 무작위 UUID로 바꾸고 파일 버퍼를 입력했다. 파일별 첫 실행은 새 브라우저 페이지에서 시작한다. 나머지 실행은 OCR 조각 캐시를 사용할 수 있으므로 독립적인 정확도 표본 30개라는 의미는 아니다. 조건은 처음 가져오기, 재가져오기, 운지 수정, 현/음높이 이동, 같은 구간 두 번 붙여넣기, 저장·다시 열기다. 페이지·마디·음표 수, 재생 가능 여부, 진행률, 브라우저 예외와 반복 결과의 동일성을 검사했다.

| 파일 | 페이지 / 마디 | 입력 운지·뮤트 | 검토 마디 |
| --- | ---: | ---: | ---: |
| A Little Further | 2 / 40 | 467 | 21 |
| Flower Dance | 3 / 63 | 845 | 37 |
| 너에게난-자탄풍 | 3 / 79 | 3,359 | 79 |
| 모든 날 모든 순간 | 3 / 57 | 992 | 0 |
| 소나기 | 3 / 63 | 1,901 | 2 |

OCR 캐시를 사용한 실행은 15회이며, 첫 실행 다섯 회는 모두 캐시 0건이었다. 첫 인식은 Flower Dance 약 77초, 자탄풍 약 264초, 모든 날 모든 순간 약 2.3초, 소나기 약 2.7초였다. 같은 컴퓨터의 이번 실행 값이며 이미지 PDF에는 여전히 긴 처리 시간이 필요하다.

소나기와 모든 날 모든 순간의 120마디 전체 운지·리듬·검토 상태는 변경 전과 동일했다. 이는 회귀 검사이며 정답률이 아니다. 모든 날 모든 순간의 수기 정답 9마디도 운지와 전체 리듬이 일치했다.

배포 빌드를 격리된 Chrome에서 열어 Flower Dance와 모든 날 모든 순간을 파일 입력으로 가져왔다. 전체 페이지 이동, 실제 운지 편집, 오선보 생성, 저장 후 재열기를 통과했고 메트로놈을 끈 상태에서 악기 PCM 신호를 확인했다. 모든 날 모든 순간 37마디에서 바뀐 운지 두 개와 반복 슬래시 여섯 개가 표시된다. 1440/1024px 데스크톱에서는 생략 켜기/끄기·실행 취소·선택 구간·인쇄·재생·저장 재열기를, 390px 모바일에서는 데스크톱 전용 버튼이 생성되지 않음을 검사했다. 브라우저 예외는 없었다.

## 한계와 적용

Flower Dance에도 누락이 남아 있으며 모든 파일의 완전 자동 전사는 아직 보장하지 않는다. **자탄풍은 79마디 모두 검토가 필요하며 이번 결과에서 자동 반복 운지 생략은 적용되지 않았다.** 리듬·운지가 미확정인 부분은 생략 표시로 숨기지 않는다. 일반 이미지 점음표, 복잡한 다성부 및 4/4 이외 박자 등 기존 제한도 남는다.

기존에 저장한 악보는 바꾸지 않는다. 개선된 결과를 보려면 PDF를 새로 불러온다. 화면 검증은 격리된 테스트 브라우저에서 진행했으며 사용자의 실제 브라우저 악보 보관함을 채운 작업은 아니다.

## 재현

`scripts/compare-pdf-tab-folder.mjs whole`로 폴더 목록을 만든 뒤 개발 서버 5174, 배포 미리보기 5175를 실행한다. Playwright 경로는 설치 환경에 맞게 지정한다.

```powershell
$env:PDF_TAB_MATRIX_OUTPUT='artifacts/pdf-tab-adaptive/release'
$env:PDF_TAB_CASES='0,1,4,5,7,9'
$env:PDF_TAB_BLIND_NAMES='1'
node scripts/verify-pdf-tab-100.mjs 1 4 6 0 3
node scripts/audit-pdf-tab-flower.mjs artifacts/pdf-tab-next/final/1-analysis.json artifacts/pdf-tab-adaptive/release/1-analysis.json
$env:PDF_TAB_QUALITY_OUTPUT='artifacts/pdf-tab-adaptive/release'
node scripts/measure-pdf-tab-accuracy.mjs artifacts/pdf-tab-next/final/0-analysis.json artifacts/pdf-tab-adaptive/release/0-analysis.json
node scripts/verify-pdf-tab-golden.mjs artifacts/pdf-tab-adaptive/release/4-document.json
$env:PDF_TAB_APP_ORIGIN='http://127.0.0.1:5175'
$env:PDF_TAB_UI_OUTPUT='artifacts/pdf-tab-adaptive/ui-final'
node scripts/verify-pdf-tab-playback-ui.mjs 1 4
```

실제 PDF·이미지·분석 JSON은 Git에서 제외된 artifacts에 보관한다. 평가용 수기 데이터는 tests/fixtures에 있으며 앱 번들에서 참조하지 않는다.
