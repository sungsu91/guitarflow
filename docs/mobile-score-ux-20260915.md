# 모바일 악보 입력 개편 검증 — 2026-09-15

> 후속 변경: 사용자 요청에 따라 TAB 숫자 입력 뒤 자동 이동을 제거했다. 한 자리·두 자리 프렛 모두 현재 위치에 머무르며 다음 위치는 화살표로 선택한다. 숫자 입력만으로 다음 마디를 자동 생성하지 않는다. 아래 최초 검증의 자동 이동 항목은 이전 동작의 기록이며, 최신 동작은 `scripts/verify-fret-stay.mjs`에서 모바일·데스크톱 모두 검증했다. 두 자리 프렛 조합과 직접 피킹의 이동 규칙은 유지한다.

## 적용 결과

모바일에 전용 `MobileScoreInput` 화면을 추가하고, 기존 ScoreEditor의 문서·명령·실행 취소·저장·컴파일을 그대로 연결했다. 데스크톱 속성 패널과 키보드 입력은 유지했다. 이번 작업은 로컬 프로젝트에 적용했으며 배포하지 않았다.

- 상단: 뒤로가기, 악보 편집 제목, 실행 취소/다시 실행, 저장만 배치.
- 중앙: 현재 마디 시작부터 오른쪽 끝선까지 너비 맞춤. 여러 마디는 아래로 이어지고 악보 영역만 스크롤한다. 확대 상태에서 가로 스크롤이 가능하다.
- 하단: 공간 방향에 맞는 커서 버튼 → 음 길이 → 숫자/X/삭제 → 일괄 피킹 → 직접 피킹 → 빈 마디/보기/상세 → 재생/BPM 순서.
- 높이와 safe-area를 실제 패널 크기로 계산한다. 상세 설정은 패널 바로 위의 작은 시트이며 기존 선택과 스크롤을 유지한다.
- 모바일에서는 음표 위 스와이프도 기본적으로 악보 스크롤이다. 기존 음표 이동 기능은 상세의 ‘음표 드래그 이동’에서 켤 수 있다. 데스크톱 드래그는 유지한다.
- 보관함의 주요 네 버튼과 검색/정렬을 44px 높이의 작은 직사각형으로 정리했다. 선택은 갈색 계열이며 공통 테마의 광택/그림자 충돌을 해당 모바일 화면 안에서만 차단했다.
- 하단 안내는 ‘간단 악보는 빠른 연습용입니다. 정밀한 악보 편집은 전문 악보 프로그램을 이용해 주세요.’로 변경했다.

## 입력과 데이터

숫자 버튼은 모바일 키보드나 별도 입력창을 열지 않고 공유 TAB 입력 명령을 호출한다. 선택이 오선보 모드였더라도 하단 숫자판은 프렛 입력이다. 숫자 입력 후 같은 기타 줄의 다음 시간 위치로 이동하며, 줄 변경은 위/아래 버튼으로 한다.

10–19는 첫 숫자 1을 화면에 즉시 입력하고 420ms 동안 두 번째 숫자를 기다린다. 두 자리 확정 후 이동한다. 2→3은 빠르게 눌러도 별개의 음이다. 20–24가 필요하면 ‘두 자리’ 옵션을 켠다. 기존 데스크톱 두 자리 입력 옵션은 유지했다. 타이밍만으로 모든 연속 단음과 두 자리 숫자 의도를 동시에 구별할 수 없어 이 구분을 화면에 안내한다.

`nextEntry`는 박자표와 음 길이로 마디 끝을 계산한다. 마지막 마디가 차면 빈 다음 마디를 추가한다. 4/4의 4분음표 다섯 번째, 8분음표 아홉 번째, 16분음표 열일곱 번째를 같은 줄로 계속 입력할 수 있다. 기존 한도인 64마디는 유지한다. 탐색이나 피킹 입력만으로 빈 마디를 추가하지 않는다.

X는 기존 이벤트에 선택적 `dead` 플래그를 저장한다. TAB X와 오선보 X 음표, 짧은 무음정 합성 타격음으로 연결한다. 일반 음을 입력하면 dead를 해제한다. 쉼표로 전환하거나 마지막 음을 삭제하면 남은 피킹·붙임줄·dead도 정리한다.

문서 버전 2와 기존 JSON 로컬 저장 키는 유지했다. 선택적인 dead 필드만 추가했으므로 기존 악보에 별도 변환이 필요하지 않다. 기본곡/사용자 편집본 구분도 유지한다. PDF Blob 저장은 기존 IndexedDB 구조 그대로이며 JSON 악보와 합치지 않는다.

## TAB 리듬과 피킹

TAB 리듬은 기본 꺼짐이며 ‘보기 → TAB 리듬 표시’로 켠다. 기존 음 길이와 onset으로 SVG 기둥/빔을 파생하며 원본 음표 데이터에는 저장하지 않는다. 숫자는 원래 줄에 유지한다.

6번줄에서 첫 빔 중심까지 `2 × 줄 간격 + 10` SVG 단위, 두 번째 빔까지도 30 단위(줄 간격 13의 약 2.3배)를 확보했다. 기둥은 프렛 위치 아래에서 외부 빔까지 내려온다. 악보 높이에 55 단위를 추가하여 피킹 기호와도 분리했다. TAB-only에서도 렌더러의 표준 쉼표 기호를 재사용한다.

8분음표는 1단, 16분음표는 2단 빔이다. 단순박자는 박 단위, 6/8 등 복합박자는 점4분 단위로 묶고 쉼표/마디 경계를 넘지 않는다. 오선보의 기본 묶음은 [VexFlow 공식 Beam 문서](https://public.vexflow.com/build/docs/beam.html)의 박자표별 묶음을 사용한다. TAB 빔과 피킹은 별개의 표시이다.

일괄 피킹은 전체 악보의 연주 이벤트에 모두 다운/모두 업/다운·업 교대를 적용한다. 직접 피킹은 선택한 이벤트의 pickStroke 하나만 수정하고 다운/업 후 다음 기존 입력 위치로 이동한다. 지움은 해당 표시만 제거한다. 화음의 음마다 피킹을 중복 저장하지 않는다. 기호 아래에 24×26 SVG 단위 터치 영역을 두며 TAB 숫자 영역과 떨어뜨렸다. 표시를 터치하면 해당 이벤트를 선택하고 하단 버튼으로 바꾼다.

## 재생과 PDF

기존 ScorePlayback과 scoreTimeline을 유지하면서 기존 useEtudeMetronome의 AudioContext/시작 시각을 공유하도록 연결했다. 오선보와 TAB에 같은 이벤트 진행 강조를 표시한다. 재생 중 악보 위치를 누르면 해당 시점으로 이동한다. 박 중간에서 시작하면 메트로놈은 다음 정확한 박 경계에서 클릭한다. 공용 사운드 버스/볼륨도 재사용한다.

PDF는 ‘페이지 너비 맞춤’에 더해 ‘전체 페이지 보기’를 제공한다. 전체 페이지는 실제 PDF 뷰포트의 너비와 높이 중 작은 배율을 택하며 페이지/확대 상태를 기존 저장에 연결한다. PDF를 음표 데이터로 변환하거나 보표를 분리하지 않는다.

## 성능

원본 문서를 매 입력마다 다시 생성하지 않는다. 기존 구조적 공유, WeakMap 마디 컴파일 캐시, memoized 마디 SVG 및 Shadow DOM 격리를 유지한다. 재생 강조/선택 커서는 별도 SVG 요소만 갱신한다. 수정되지 않은 마디의 음악 데이터와 SVG drawCount가 유지되는지 검사했다.

32마디 뒤쪽에서 30개 입력 시 앞 31마디의 drawCount는 유지되었다. 데스크톱 30음 입력은 컴파일 30회/해당 마디 SVG 30회였고, 64마디 마지막 수정 검사도 통과했다. 화면 전체 React 갱신이 전혀 없다는 뜻은 아니며 무거운 기보/컴파일 범위를 제한한 것이다.

## 남은 한계

- 실제 iPhone/Safari와 Android/Galaxy 기기에서 터치·브라우저 주소창·노치 변화·소리를 직접 확인하지 않았다. 이번 결과는 Chrome 모바일 에뮬레이션이다.
- 셋잇단음표는 현재 문서 형식이 지원하지 않아 임의의 3 표시를 만들지 않았다.
- H/P/SL 등 기존 주법은 음높이·길이 확인용 합성 재생이며 실제 기타 음색/잔향/주법을 완전히 재현하지 않는다. 메트로놈과 악보 진행은 공통 시계를 사용하지만 실제 기기 음향 지연은 미검증이다.
- 동일 화면에 많은 음을 넣으면 너비 맞춤 상태의 기호가 작아진다. 확대/축소와 악보 스크롤을 제공하며 정밀 편집은 상세 설정을 사용한다.
- 64마디 한도, 20–24 입력 시 명시적 두 자리 모드, 복잡한 박자/불규칙 빔 편집은 기존 단순 편집 범위의 제약으로 남는다.
- 피킹행은 조밀한 32px 버튼이다. 숫자 키는 44px, 방향/길이는 40px이며 실제 손가락 오입력 평가는 기기 확인이 필요하다.


## 후속 정리: 메뉴 중복·피킹·마디 배치

- ‘보기 · 메뉴’와 ‘상세’가 같은 메뉴를 반복하던 구조를 메뉴 버튼 하나로 통합했다. 내부의 메뉴/음표/마디/곡 정보 탭에서 해당 기능만 표시한다.
- 일괄과 직접 피킹을 좌우 2열로 배치했다. 숫자/화살표/상태 글자의 크기와 굵기를 높였다.
- 악보 위에 ‘한 줄 1·2·3·4마디’를 항상 표시한다. 기본값은 1마디이다. 3~4마디의 작은 화면은 전체 배치 확인용으로 안내한다.
- 줄 편집을 켜면 마디부터 새 줄을 만들거나 합친다. 손잡이를 아래로 끌면 줄 나누기, 위로 끌면 해당 강제 줄바꿈 해제이다. 악보 연주 순서를 바꾸는 기능이 아니다.
- `measureLayout.js`는 안정적인 마디 ID로 화면 grid 위치만 계산한다. 음악 문서에는 배치를 기록하지 않으며 현재 편집창의 보기 설정이다. 배치 변경 후 저장한 음표 데이터가 동일함을 검사했다.
- 마디의 화면 너비에 맞춰 SVG 기보 폭도 조절하여 전체 페이지 축소처럼 기호가 지나치게 작아지는 현상을 줄였다. 배치가 달라지면 필요한 SVG는 다시 기보하지만 음표 입력으로 관계없는 마디를 다시 생성하지 않는다.
