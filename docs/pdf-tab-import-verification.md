# PDF TAB 인식·편집·재생 검증

검증일: 2026-09-30. 사용자가 지정한 Desktop/sheet music의 **PDF 10개, 28페이지**를 사용했다. 최종 수정본에서 파일별 10가지 조건, **100회 전체 파일 가져오기·편집·저장·재생 데이터 검사**를 완료했다. 모두 프로그램 흐름 검사를 통과했다. 이것은 **악보 인식 정답률 100%라는 뜻이 아니다.** 아래에 정답 비교, 누락, 실패한 해상도 조건을 따로 적었다.

개선 중 첫 100회 검사는 별도 보관했고, 이후 OCR 여백·피킹 표시 제외·줄기 끊김을 보완한 최종 코드로 100회를 다시 실행했다. 중단된 실행은 완료 횟수에 포함하지 않았다.

## 100회 검사 조건

각 파일마다 다음 10가지를 실행했다. 모든 경우 실제 PDF 파일을 다시 선택하고 모든 페이지를 렌더링·검출·문서 변환했다.

1. 자동 확대를 포함한 첫 가져오기
2. 같은 파일 다시 가져오기 및 결과 동일성
3. 2.5배 단일 해상도 실험
4. 4.5배 단일 해상도 실험
5. 프렛 변경
6. 운지를 다른 현/음높이로 이동
7. 박 전체 복사
8. 같은 범위에 두 번 붙여넣기
9. 마디 복제
10. 저장 후 다시 열기

모든 조건에서 컴파일 오류, ID 중복, 음 개수 변화, MIDI 음높이, 초안 재생 가능 여부, 페이지/마디 보존, 저장·다시 열기, 진행률 역행을 확인했다. 반복 붙여넣기는 덧붙이지 않고 같은 구간을 대체했다. 수정·이동에서 원하지 않는 음 증가가 없었다.

동일한 숫자 이미지의 OCR 캐시를 사용한 실행은 48회다. **100회의 독립 OCR 정확도 표본이 아니다.** 파일 로드·페이지 렌더링·구조 분석·문서 생성·편집·저장은 매번 실행했다. 캐시는 메모리 문자열 기준 32MiB/20,000개 상한과 최근 사용 순 교체를 적용한다.

## 정답과 직접 비교한 범위

### A Little Further: 40마디 전체

폴더 PDF와 일치하는 기존 작곡 원본 daylightDocument를 **검증에만** 사용했다. 생산 인식 코드에 곡의 정답을 넣지 않았다. 쉼표를 제외한 이벤트 수와 순서가 40마디 모두 일치하여 같은 위치의 현·프렛을 비교했다.

| 항목 | 이전 | 최종 |
| --- | ---: | ---: |
| 원본 508개 중 맞게 입력된 운지 | 184 (36.2%) | 400 (78.7%) |
| 미입력 운지 | 324 | 108 |
| 비교 범위에서 틀리게 확정한 운지 | 0 | 0 |
| 음표 길이 일치 마디(쉼표 제외) | 16/40 | 37/40 |
| 쉼표까지 전체 리듬 일치 마디 | 7/40 | 17/40 |
| 운지·리듬 모두 완전히 일치한 마디 | 0/40 | 4/40 |

따라서 개선 후에도 이 이미지 PDF를 완성 악보로 자동 카피했다고 볼 수 없다. 특히 이미지 쉼표를 읽지 못해 뒤 음의 박 위치가 당겨지는 경우가 남는다. 미확정 리듬은 임시 편집 배치이며 원본 리듬 보증이 아니다.

### 모든 날 모든 순간: 3페이지에 걸친 9마디

원본에서 별도로 옮겨 적은 1·2·3·4·37·45·46·49·57마디의 **운지 207개와 리듬 이벤트 76개**가 일치했다. 첫 4마디뿐 아니라 후반의 코드 변경, 반복 슬래시, 온쉼표, 8분쉼표, 점음표, 셋잇단을 포함한다. 전체 57마디를 모두 수기 채점한 결과는 아니다.

### 인사: 첫 4마디

원본 TAB 6줄과 연결된 빔을 직접 읽은 기준으로 각 마디의 리듬은 4 8 16 16 16 16 8 8 16 16이다. **4/4마디, 40개 리듬**이 일치했다. 원본 218개 운지 중 144개가 맞고 74개는 미입력이며, 틀리게 확정한 운지는 0개, 리듬 열 밖의 추가 확정 운지는 0개다.

## 발견한 원인과 수정

- TAB 가로줄 제거가 숫자 가운데 획까지 끊었다. 위·아래를 가로지르는 숫자 획을 보존했다.
- 흐린 두 빔 사이가 합쳐졌다. 줄기와 빔에 다른 이진화 임계값을 사용했다.
- 줄기 밖의 다운·업 피킹 표시가 두 번째 빔으로 들어갔다. 줄기 끝 바깥을 제외했다. 실제 줄기에 있는 1~2픽셀 끊김만 좁게 연결한다.
- 작은 OCR 입력까지 캔버스 여백을 넓히면 같은 숫자의 신뢰도가 떨어졌다. 작은 입력은 기존 여백을 유지하고 확대할 때만 넓힌다.
- 확대 결과가 항상 좋지는 않았다. 기본/확대의 TAB·마디 구조가 다르면 버리고, 기존 확정 운지를 잃는 확대 마디도 채택하지 않는다. 같은 위치의 일치하는 읽기만 보완하며 결과를 이어 붙이지 않는다.
- 긴 음을 박 경계에서 나눌 때 음 ID가 중복됐다. 분리한 음에 새 ID를 준다. 마디 복제 시 셋잇단 그룹 ID도 새로 만들어 원본까지 선택되는 현상을 막았다.
- 미확정 표시 하나가 악보 전체 재생을 막았다. PDF 초안은 입력된 운지로 미리 듣게 하되, 실제 잘못된 프렛·겹침·타이 오류는 계속 차단한다.

## 실제 화면·오디오·회귀 검증

Chrome 제작실에서 실제 파일 선택 → 전체 페이지 가져오기 → 오선보+TAB → 운지 입력 → 저장 → 다시 열기 → 재생을 확인했다. 이미지 PDF에서는 Alt 드래그로 현 이동 후 Ctrl+C/Ctrl+V 두 번도 실행하여 음 개수와 ID 중복을 확인했다. 메트로놈을 끈 상태의 Web Audio 출력에서 0이 아닌 기타 PCM 신호를 측정했다. 미확정이 남은 저장 악보의 연습 화면에서도 시작·일시정지·정지가 동작했다. 스피커에서 사람이 청취해 음색을 평가한 검사는 아니다.

음높이와 오선보는 현·프렛·튜닝·카포에서 자동 계산한다. 오선보 OCR 누락이 재생 차단 원인이 아니었다. ?는 무음이며 미확정 리듬은 임시 배치대로 재생한다. 최초 열기에서 악보 소리를 켜며 사용자가 이후 끌 수 있다.

전체 자동 테스트 **1,533개 통과**, production build 성공. 개발 체크·하단 개발 안내가 없고 모바일 390px에서 PDF 가져오기 UI가 노출되지 않음을 확인했다. 기존 shooter 테스트의 오래된 파일 허용 목록에는 이미 main에 배포된 guitarArticulation 모듈만 명시적으로 추가했다. 게임 판정·충돌 비교는 그대로 유지했다.

## 남은 제한과 재현 자료

이미지 쉼표·점·복잡한 겹침, 12/8 등 현재 편집기가 지원하지 않는 박자, TAB에 리듬이 없고 오선보에만 있는 파일, 여러 기타 파트가 한 페이지에 있는 파일은 수동 검토가 필요하다. 템포·조표·튜닝·카포·주법은 자동 확정하지 않는다. PDF의 모든 운지와 리듬이 확실히 카피되는 범용 변환기는 아직 아니다.

재현 명령과 기능 설명은 [PDF TAB 가져오기](pdf-tab-import.md)를 참조한다. 로컬 상세 결과는 `artifacts/pdf-tab-100/final/matrix.json`, `artifacts/pdf-tab-100/final/summary.json`, `artifacts/pdf-tab-100/accuracy.json`, `artifacts/pdf-tab-100/insa-accuracy.json`과 UI 로그에 보관한다. 실제 PDF·이미지·상세 JSON은 Git/배포에 포함하지 않는다. 최초 100회 결과는 `artifacts/pdf-tab-100/round1-matrix.json`에 별도 보존했다.
