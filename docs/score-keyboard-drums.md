# 악보제작실 악기별 입력

기타·베이스·우쿨렐레는 기존 현/프렛/TAB 규칙을 유지한다. 피아노와 드럼은 `scoreInstruments.js`의 프로필을 사용하며 현이나 프렛으로 음높이를 계산하지 않는다.

- 피아노: MIDI 0–127, 실제 음높이, 높은음자리표·낮은음자리표의 양손 큰보표.
- 기존 `keyboard` 악보는 데이터 손실 없이 `piano`로 읽고 저장한다. 악기 목록은 기타·베이스·우쿨렐레·피아노·드럼이며 MIDI 연결과 화면 건반은 입력 기능으로 유지한다. 실제 장치의 건반 수를 자동 탐지하지 않는다.
- 드럼: `DRUMS`에 정의한 GM 드럼 세트 19개 음. 킥·스네어·탐은 일반 머리, 하이햇·심벌은 X 머리. 지원하지 않는 MIDI 번호는 안내하고 입력 전체를 취소한다.

드럼 번호 참고: [General MIDI percussion map](https://www.cs.cmu.edu/~music/cmp/archives/cmsip/readings/GMSpecs_PercMap.htm). 보표 위치는 `DRUMS`에 명시한 앱의 드럼 세트 범례이며 모든 타악기 표기 관습을 포괄하지 않는다.

## 공유 데이터와 입력

건반/드럼 음표는 `id`, `midi`를 저장하고, 건반 음표는 `hand` (`left` / `right`)를 추가한다. MIDI 실제 음높이가 기준이며 기타 옥타브 이조나 카포를 적용하지 않는다. 저장용 `tuning`은 빈 배열이다. 재생 컴파일 시에만 MIDI별 독립 음성 키를 기존 재생 타임라인에 연결한다.

화면 건반은 기본적으로 선택 음길이로 입력 후 자동 전진한다. 화음 토글을 켜면 같은 위치에 중복 없이 음을 추가하고 → 또는 토글 해제로 한 번 확정한다. 드럼 패드의 동시음 입력은 기존 방식을 유지한다. MIDI 장치 입력은 기존 70ms 화음 묶음과 한 번의 커서 이동을 유지한다. 점음표·셋잇단음표·마디 용량·저장·실행 취소는 기존 공통 로직을 재사용한다. 화면의 손 선택은 MIDI에도 적용된다. 왼손/오른손 버튼은 입력 성부만 정하며 음역을 제한하거나 기존 음을 이동하지 않는다. 건반 눌림은 포인터/키 해제·취소 때 지운다.

피아노 이벤트는 `voice: right | left`와 마디 내 `onset`을 저장한다. 성부마다 길이·쉼표·셋잇단과 커서가 독립적이며 동시 시점은 공통 Formatter 시간축으로 정렬한다. 기존 혼합 손 화음은 편집기를 열 때 두 성부로 나누고 음높이·손·길이·붙임줄을 보존한다. 서스테인 페달 기보는 포함하지 않는다. MIDI는 단계 입력이며 실시간 녹음이 아니다.

피아노와 현악기 사이의 변경은 가능한 경우 실제 음높이를 유지한다. 음역이나 운지로 변환할 수 없거나 드럼과 음높이 악기를 서로 바꾸면 기존 저장/새 악보/취소 절차를 사용한다. 피아노로 바꿀 때 기타 주법과 운지표를 제거하고 코드명은 화성 정보로 보존한다.

## 화면과 재생

기존 모바일/데스크톱 분기를 유지하며 공통 상태와 동작을 공유한다. 프렛 패드와 `KeyboardInput`은 조건부 렌더링한다. 건반/드럼에서는 튜닝·카포·자동 TAB·피킹 도구를 생성하지 않는다. `KeyboardScore.js`는 큰보표/타악기 보표, 쉼표, 점음표, 셋잇단, 빔, 붙임줄, 반복 기호를 렌더링한다. 편집, 보기, 인쇄가 같은 렌더러를 사용한다.

피아노는 기존 피아노 샘플, 드럼은 킥·탐의 발진기와 스네어·하이햇·심벌의 필터 노이즈 합성을 사용한다. 드럼 소리는 참고용 합성 음색이며 샘플 드럼 라이브러리가 아니다. 하이햇 계열은 같은 음성 그룹을 공유하여 닫힌 하이햇이 열린 하이햇 울림을 끊는다.

## 검증

- `tests/score-keyboard-drums.test.mjs`: 악기별 음역, 현 제한 없는 화음, GM 드럼 검사, 직렬화, 손 배정, 점/셋잇단, 삭제/붙임줄, 악기 변환, 독립 재생 음성.
- `scripts/verify-score-instruments.mjs`: 360/390px 모바일 및 1440px 데스크톱 화면 입력, MIDI 드럼 입력 시뮬레이션, 손 변경/실행 취소, 저장, 인쇄, 재생, 다시 열기, 극단 음역 렌더링, OfflineAudioContext 드럼 출력 검사.
- 실제 MIDI 하드웨어와 실물 모바일 기기는 검증하지 않았다.

검증 결과: 전체 단위 테스트 1,110개 통과, 프로덕션 빌드 성공. 새 악기 브라우저 검증은 360/390/1440px에서 통과했다. 기존 튜닝·카포·MIDI 회귀 스크립트도 모바일/데스크톱, 테마와 권한 시나리오 전체 통과했다. 로그는 `output/instruments-tests.txt`, `output/instruments-browser.txt`, `output/instruments-regression-browser.txt`, `output/instruments-build.txt`에 기록했다.


## 피아노 연속 입력 검증

`tests/piano-input.test.mjs`는 자동 전진·성부별 편집·쉼표·점음표·셋잇단·붙임줄·저장 호환을 검증한다. `scripts/verify-piano-input.mjs`는 390/1440px에서 화면 건반, 독립 손 커서, 화음 확정, MIDI 화음 묶음, 실제 브라우저 터치 취소, 기존 음 수정, 실행 취소/다시 실행, 저장/재열기를 검증한다.

최신 피아노 연속 입력 검증: 전체 테스트 1,131개와 빌드 통과. 390/1440px 브라우저에서 자동 전진, 양손 독립 리듬, 화음·MIDI 묶음, 점음표·셋잇단, 포인터 이탈·터치 취소, 기존 음 수정, 실행 취소·복원, 여러 줄 자동 스크롤을 확인했다. 기존 악기·드럼 입력 회귀는 360/390/1440px에서 통과했다. 실제 MIDI 하드웨어는 사용하지 않았다.
