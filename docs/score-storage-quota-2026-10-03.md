# 제작 악보 저장 한도 오류 수정

사용자 화면의 `fretiva.etude.library.v2 exceeded the quota`는 localStorage 저장 실패였다. 이전 검증은 빈 브라우저 프로필에서만 실제 81마디를 저장했으므로 사용자의 기존 데이터로 공간이 찬 조건을 놓쳤다.

## 변경

- 브라우저 제작 악보 저장소를 `fretiva.score.library.v3` IndexedDB로 전환했다. 기존 `scoreLibrary.js`의 검증·제목 중복 처리·악보 정규화 규칙을 공유한다. 모바일/데스크톱 UI는 그대로 분리한다.
- 최초 데이터베이스 트랜잭션에서 기존 v2 또는 v1 데이터를 읽어 이전한다. localStorage 원본은 지우거나 덮어쓰지 않는다. 이전 이후에는 과거 복사본을 다시 합치지 않아 삭제한 악보가 되살아나지 않는다.
- 트랜잭션 완료 후에만 저장 성공을 반환한다. 동시에 저장해도 변경을 유실하지 않도록 읽기와 쓰기를 하나의 트랜잭션에서 수행한다. 저장 실패 시 기존 데이터와 현재 편집 초안은 유지한다.
- 저장창은 비동기 완료를 기다리고, 중복 저장·저장 중 닫기를 막는다. 실제 성공 후 경고를 없앤다. 실패 안내에는 악보실 저장 재시도·파일 내보내기·안내 닫기를 제공한다. 안내만 닫아도 초안을 저장 완료로 처리하지 않는다.
- 악보실의 읽기·이름 변경·삭제·새로고침 후 읽기도 같은 저장소를 사용한다. IndexedDB 자체가 차단되거나 실제 저장 공간이 부족한 경우에는 성공을 가장하지 않는다.

## 검증

`scripts/verify-score-storage-quota.mjs`는 사용자 브라우저와 별개의 프로필에서 수행한다.

- localStorage에 약 5.23백만 문자의 테스트 데이터를 채우고, 기존 방식의 저장 실패를 재현했다.
- 기존 악보를 보존한 채 81마디 초안을 IndexedDB에 저장했다. 원본 localStorage 값은 변경되지 않았다.
- 동시 저장 3건, 이름 변경, 삭제 후 다시 읽기, 저장 요청 성공 직후 트랜잭션 강제 중단을 검사했다. 중단한 변경은 성공으로 반환되거나 기존 악보에 반영되지 않았다.
- 모바일 440px·데스크톱 1440px에서 81마디 저장 → 새로고침 → 실제 악보 불러오기 화면 → 편집기 열기까지 통과했다.
- 두 화면에서 IndexedDB 할당량 오류를 강제로 발생시켰다. 가져온 초안을 유지하고 저장창에 오류를 표시했으며, 실패 조건 해제 후 재시도하면 저장창과 안내문이 사라졌다.
- 전체 단위 테스트 1,745개 통과, 실패 0개. 배포용 빌드 및 개인 악보의 배포 제외 검사 통과. 기존 번들 크기 경고는 남아 있다.
- 배포용 화면에서도 오선보 PDF 변환 후 저장, 모바일 사진 2장을 합친 8마디 저장을 재검사해 통과했다. 이 검사도 새 IndexedDB에서 저장 결과를 읽어 확인한다.

진단 로그·스크린샷: `artifacts/score-storage-quota/`. 실제 휴대폰 OS의 저장 공간 부족이나 Safari 동작을 확인했다는 의미는 아니다.

## 표시한 8분음표 확인

사용자가 표시한 ‘풀잎사랑’ 1페이지의 한 줄 빔 음표는 8분음표다. 이전 실제 모델 결과와 저장된 변환 문서를 대조하면 9마디 끝의 4음, 11마디의 7음, 12마디 앞의 4음은 이미 `duration: "8"`, 한 음당 240틱(반 박)으로 저장되어 있다. 11마디 첫 8분쉼표와 12마디 마지막 2분음표도 구분되어 있다.

모든 오선보 결과를 원본 대조 대상으로 표시하는 ‘미확정’ 문구가 인식 실패 개수로 읽힐 수 있었다. 오선보 결과에는 ‘원본 대조 전’으로 표시하고 그 의미를 안내하도록 수정했다. 자동으로 검토 완료 처리하지 않는다.

전체 재생을 막는 별도 오류도 있다. 기존 실제 문서의 36마디는 4.25박, 41마디는 5박으로 4/4 한 마디를 초과한다. 그 외 음가 부족·붙임줄 누락·음높이 오류가 남아 있다. 이 저장 수정으로 OMR 정확도까지 해결됐다고 주장하지 않는다. 표시된 8분음표 패턴의 음가와 시작 시각을 유지하는 회귀 테스트를 추가했다.
