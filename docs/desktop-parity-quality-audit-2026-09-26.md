## 주요 수정과 데이터 보존

- React Activity로 리듬·악보·오디오의 입력 중 상태를 보존하고 숨길 때 효과/재생을 정리한다. 기존 강한 CSS가 숨긴 화면을 다시 노출하던 문제와, 캐시된 미니반주 화면의 body 팝업이 남는 문제를 수정했다. 모바일/데스크톱 UI를 복제하지 않았다.
- 지판 컨트롤/카탈로그 좌우 배치, 사이드바 긴 영어 줄바꿈, 박자 HUD 겹침, 슈팅/플로팅 도구 위치를 조정했다. 기존 접기/펼치기는 유지했다.
- 오디오 설명 크기·행간·명암을 보완하고 ‘MIX SAVE’ 안내를 실제 ‘하나로 저장 / Save mix’ 조작에 맞췄다. 리듬 가이드·진행 표시·인쇄의 영어 누락을 보완했다.
- 모바일 리듬 단계 버튼을 2열/줄바꿈으로, 360px 악보 도구/BPM을 잘리지 않게 보정했다. 데스크톱 추가 버튼은 플랫폼 조건으로 렌더링한다.
- 최종 육안 점검에서 다크 테마 가이드가 본문 옆으로 밀리고 낮은 대비로 표시되는 CSS 충돌을 발견해 수정했다. 모든 요청 크기에서 팝업의 고정 위치·모바일 전체 너비/높이·다크 배경도 검사하도록 보강했다.
- 저장 DB/키/문서 형식, 튜너·슈팅 판정, 운지·음길이·박자 계산은 유지했다. 사용자 작성 제목/음악 데이터는 번역하지 않는다. 사용자 실제 보관함을 열거나 삭제하지 않았다.

## 보안 점검과 수정

- Vite **8.3.1**, PostCSS **8.5.28**, nanoid **3.3.19**로 갱신. npm audit **high 3건 → 전체 0건**. 알려진 의존성 경고 결과이며 보안 전체의 보증은 아니다. 공식 확인 근거: [Vite 공지](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff), [PostCSS 공지](https://github.com/postcss/postcss/security/advisories/GHSA-fxqj-rqcc-2cmp).
- 소스 저장 API 3개는 loopback·로컬 Host·JSON·동일 Origin/Fetch-Site를 확인한다. 실제 개발 서버에서 외부 Origin/단순 POST는 403, 동일 Origin의 잘못된 JSON은 400: **9개 요청 통과**, 파일 쓰기는 하지 않았다.
- 배포 CSP에 base-uri/object-src/form-action 제한과 Permissions-Policy를 추가했다. 기존 프레임 차단/nosniff/referrer 정책은 유지했다. **운영 HTTP 응답 헤더는 미검증**이며 완전한 script-src CSP 적용을 주장하지 않는다.
- 소스 비밀키 패턴·위험한 HTML/eval 경로 검색에서 노출을 발견하지 않았다. Git 전체 이력·외부 계정·서버 비밀 관리까지 검사한 것은 아니다. 외부 이미지/링크/오디오 출처 정책은 유지했다.
- PDF 백업 오류 안내를 보완했다. 렌더러의 eval/XFA 제한, 로컬 worker, 32MB·8페이지·2문서 캐시 상한을 확인했다.
- 오디오 가져오기에 **파일당 100MB**, 한 번에 보관할 디코딩 결과 **256MB** 상한과 안내를 추가했다. 디코더 내부 일시 메모리 피크까지 강제 제한하는 기능은 아니다.
- Vite 갱신으로 public JSON의 모듈 import가 거부되는 문제는 스킨 manifest 2개를 src로 이동해 해결했다. manifest 값과 스킨 이미지/음악 판정은 바꾸지 않았다.

| 항목 | eager | lazy |
|---|---:|---:|
| 초기 JS/CSS 본문 합계 | 6,259,613 bytes | 6,050,484 bytes |
| 로컬 준비 시간 중앙값* | 2,729ms | 2,656ms |
| 초기 오디오 전용 청크 | 초기 묶음에 포함 | 0개 |

**초기 약 209KB 감소**. 오디오 진입 시 전용 JS 약 63KB·CSS 약 148KB 로드를 확인했다. gzip 빌드 합계 기준 약 34KB를 초기 경로에서 분리했다. *시간은 테스트의 고정 500ms 대기와 로컬 머신 영향을 포함하므로 제품 속도 개선율로 해석하지 않는다. 초기 JS heap은 약 29~31MB로 유의미한 감소를 확인하지 못했다.*

현재 실행 경로에는 service worker 등록이 없다. PWA manifest를 유지했으며 별도 오프라인 캐시를 만들지 않았다. 큰 CSS 번들·선택한 슈팅 맵의 대형 이미지·장시간 편집/다중 디코딩은 추가 측정 대상으로 남는다.

빌드는 성공하지만 큰 청크 경고와 `Score.jsx`의 정적/동적 import 혼용 경고는 남는다. 공통 악보 렌더러의 의존성 분리와 번들 재구성은 추가 성능 작업 대상이며, 경고 한도를 올려 숨기지 않았다.

## 미검증·남은 확인 사항

설치된 plugin-management 스킬로 도구를 확인했다. 전용 보안 플러그인은 연결되어 있지 않아 사용하지 않았다. 실제 사용 도구는 소스/Node 검사, npm audit, Vite, Playwright+Edge, 로컬 개발/production preview와 이미지 확인 도구다.

- **실제 iPhone Safari, iOS 홈 화면/PWA, OS 키보드·권한 UI**: Windows에서 확인할 수 없음.
- **실물 악기·마이크·USB·MIDI·카메라, 청감/지연**: 합성 신호·가상 장치·자동 검사만 수행. 실제 판정과 장치별 코덱/동기화 확인 필요.
- **외부 공유/문의 전송**: OS 공유·SNS·이메일은 실제 전송하지 않음. 경로/모의 클립보드만 확인.
- **운영 서비스·HTTPS·응답 헤더·PWA 설치**: 배포하지 않아 미검증. 운영 전 staging에서 확인 필요.
- **저사양 장시간 부하·여러 대형 PDF/음원·저장 용량 고갈·전체 편집 옵션 및 스킨×장치 조합**: 기본 회귀를 넘는 스트레스 검증은 미수행. 브라우저 데이터 삭제/시크릿 모드의 영구 보존을 보장하지 않음.
- **추가 보안 범위**: Git 전체 이력·외부 서비스·완전한 script-src CSP·실제 서버 정책은 별도 감사 대상.

현재 코드 수정에 추가 사용자 판단은 필요하지 않다. DEV/미완성 기능은 그대로 표시했다. 운영 배포는 이 보고의 실기기/배포 전 확인을 마친 뒤 별도로 진행한다.
