# PDF TAB 추가 개선과 재검증

검증일: 2026-09-30. 비교 기준은 직전 배포 1274b86f이다. 사용자가 지정한 Desktop/sheet music의 동일한 PDF 10개를 이용했다. PDF의 정답·곡별 운지·곡 이름을 생산 인식 코드에 넣지 않았다.

## 이번에 추가한 동작

- 같은 페이지에서 서로 다른 OCR 조건의 읽기가 동의한 숫자들을 글꼴 예시로 사용한다. 최소 두 예시와 모양이 일치하고 다른 숫자와 충분히 구별되며, OCR 자체의 제안도 같은 숫자일 때만 보완한다. 복구된 숫자는 다른 숫자를 학습시키지 않는다. 페이지나 PDF를 넘어 예시를 공유하지 않는다.
- 기본·확대 이미지의 같은 마디·현·숫자 위치가 일대일로 대응할 때 양쪽의 읽기를 보완한다. 기존 리듬을 유지하면서 확대에서 잘 읽힌 숫자를 받아올 수 있다. 충돌하는 읽기는 확정하지 않으며, 음표 목록을 합쳐 중복 입력하지 않는다.
- 이미지 TAB 가운데 현 사이에 놓인 4분·8분·16분쉼표를 전체 모양으로 검사한다. 같은 열의 운지·줄기, 현 위의 숫자 모양은 제외한다. 쉼표 조각을 숫자로 다시 넣지 않는다. 박자 합계에 맞추기 위한 가짜 쉼표는 만들지 않는다.
- 아래 줄기 끝의 짧은 갈고리형 TAB 꼬리를 인식한다. 큰 꼬리가 있을 때 옆의 작은 조각을 두 번째 꼬리로 세지 않는다. 확대 결과에서 이미 읽은 쉼표나 완전한 리듬이 사라지면 원래 마디를 유지한다.
- 기능은 공유 인식 계층에 추가했다. 데스크톱 가져오기 UI와 모바일 화면 분리는 유지했다.

## 원본 정답 대조

### A Little Further: 40마디 전체

기존 작곡 원본 daylightDocument를 검증에만 사용했다. 이 파일에서의 수치이며 다른 PDF 전체에 일반화한 정확도가 아니다.

| 항목 | 직전 배포 | 이번 수정 |
| --- | ---: | ---: |
| 정확히 입력된 운지 / 508개 | 400 (78.7%) | 441 (86.8%) |
| 미입력 운지 | 108 | 67 |
| 틀리게 확정한 운지 | 0 | 0 |
| 음표 길이 일치 / 40마디 | 37 | 40 |
| 쉼표까지 전체 리듬 일치 / 40마디 | 17 | 40 |
| 운지·리듬 모두 완전히 일치 / 40마디 | 4 | 11 |

제작실로 옮긴 문서에서도 40마디 전체의 시작 박·음표 길이·실제 쉼표 24개를 원본과 비교했다. 모두 일치했다. 숫자를 놓친 음은 빈칸/무음으로 남기므로 완성된 연주 전체가 원본과 같다는 뜻은 아니다.

### 인사: 첫 4마디

수기로 옮겨 적은 218개 운지 중 직전 144개에서 **198개**로 늘었다. 20개는 미입력, 틀리게 확정한 운지는 0개, 리듬 열 밖의 추가 운지는 0개다. 4/4마디의 음가 40개도 일치했다. 이 네 마디 이외 전곡을 수기 채점한 결과는 아니다.

### 모든 날 모든 순간: 3페이지의 9마디

직접 옮겨 적은 1·2·3·4·37·45·46·49·57마디의 운지 207개와 리듬 이벤트 76개가 계속 일치했다. 별도로 텍스트 PDF 네 개의 **209마디 전체**를 직전 결과와 비교하여 음가·쉼표·프렛·검토 상태가 모두 유지됨을 확인했다. 이전 결과와의 동일성은 독립적인 정답률 검사가 아니다.

### 나는나비: 첫 4마디

원본 TAB 숫자를 직접 대조한 176개 운지 중 **88 → 153개**가 맞게 입력됐다. 23개는 미입력, 틀리게 확정한 운지는 0개다. 네 마디의 8분음표 32개도 일치했다. 전곡 운지 증가를 모두 정답으로 간주하지 않고 이 네 마디를 별도로 검증했다.

## 100회 실제 파일 재검증

이번 작업의 첫 100회 기능 검사는 통과했지만, 직전 결과와의 전체 마디 비교에서 기존 PDF 네 마디의 8분 꼬리가 16분으로 바뀐 회귀를 발견했다. 작은 꼬리 인식을 넓히며 정상 꼬리 옆의 짧은 조각까지 센 것이 원인이었다. 큰 꼬리를 우선하고 작은 갈고리는 하나만 있는 경우에 사용하도록 수정했다.

그 수정 뒤 파일당 10조건, 총 **100회**를 새로 실행했고 100회 모두 기능 검사를 통과했다. 이 표는 재검사한 최종 코드 결과다. 중간 실험과 중단된 실행은 이 수에 포함하지 않았다. 첫 100회 결과도 round1-matrix.json에 보존했다.

조건: 기본 자동 가져오기, 같은 파일 재가져오기, 2.5배/4.5배 단일 해상도, 프렛 변경, 현/음높이 이동, 박 복사, 같은 범위 두 번 붙여넣기, 마디 복제, 저장·다시 열기. 매번 실제 PDF의 모든 페이지를 렌더링하고 문서를 생성했다. ID 중복·페이지 수·마디 수·진행률·재생 MIDI·저장 내용을 검사했다.

동일 숫자 조각의 OCR 캐시가 사용된 실행은 48회다. 따라서 100개의 독립적인 OCR 정확도 표본은 아니다. 코드가 실행된다는 검사와 원본 인식 정답 검사를 구분했다.

| PDF | 페이지 | 마디 | 입력 프렛: 직전 → 이번 | 검토 마디 |
| --- | ---: | ---: | ---: | ---: |
| A Little Further · Fingerstyle Sketch · A4 인쇄 미리보기 | 2 | 40 | 400 → 441 | 29 |
| Flower Dance | 3 | 63 | 603 → 732 | 56 |
| 나는나비-윤도현 | 4 | 87 | 2373 → 3111 | 83 |
| 너에게난-자탄풍 | 3 | 79 | 2708 → 3274 | 79 |
| 모든 날 모든 순간[TAB] | 3 | 57 | 992 → 992 | 0 |
| 바람이 불어오는곳 | 1 | 20 | 290 → 290 | 20 |
| 소나기[tab] | 3 | 63 | 1901 → 1901 | 2 |
| 신호등-이무진 | 3 | 70 | 1730 → 2239 | 70 |
| 여수밤바다[TAB] | 3 | 69 | 1366 → 1366 | 63 |
| 인사-범진 | 3 | 55 | 1883 → 2200 | 54 |

총 28페이지, 603마디다. 입력 프렛 개수는 전곡 정답률이 아니며, 기존 TAB 반복 슬래시에서 적용한 운지도 포함한다. 제목·QR·코드표 운지는 사용하지 않는다.

단일 해상도 실험에서는 8건의 마디 검출 불일치가 남았다. 자동 모드는 마디 구조가 다른 확대 결과를 받아들이지 않는다. 상세 조건별 결과는 로컬 final/matrix.json에 보존했다.

## 화면·재생·회귀 검사

production 빌드의 실제 파일 선택 화면에서 이미지 PDF와 텍스트 PDF를 가져와 오선보 자동 생성, 운지 입력, 저장 후 재생을 확인했다. 이미지 PDF는 Alt 드래그와 두 번 붙여넣기도 검사했다. 메트로놈을 끈 상태에서 0이 아닌 기타 PCM 출력을 측정했고 브라우저 오류는 없었다. 새 문서를 연습 화면에서 열어 시작·일시정지·정지도 확인했다. 사람이 스피커로 청취한 음색 평가는 아니다.

전체 회귀 테스트 **1,543개 통과**, 빌드 성공. 과도한 숫자 후보는 모양 비교용 배열을 만들기 전에 기존 한도로 차단하도록 검사 순서도 확인했다. 데스크톱 1440px과 모바일 390px 검사에서 브라우저 오류가 없었고 모바일에 PDF 가져오기 버튼이 노출되지 않았다.

## 남은 한계

기준 이미지 PDF에서도 운지 67개가 아직 누락된다. 줄기·슬러와 겹쳐 잘린 숫자, 다른 위치/글꼴의 쉼표, 점음표·이미지 셋잇단, 12/8 및 박자 변경, 여러 기타 파트, 오선보에만 있는 리듬은 계속 검토가 필요하다. 이번 개선을 모든 PDF의 완전 자동 변환으로 판단하면 안 된다. 숫자 예시의 유사도와 confidence는 보정된 정답 확률이 아니다.

원본·렌더·분석 JSON은 배포/Git에 포함하지 않는다. 로컬 증거는 `artifacts/pdf-tab-next/` 아래의 `final/`, `accuracy.json`, `insa-accuracy.json`, `nabi-accuracy.json`, `ui/`, `unit.log`에 있다. 직전 결과는 `artifacts/pdf-tab-100/`에 별도로 보존했다. 새 인식 결과는 PDF를 다시 가져올 때 적용되며 기존 저장 악보를 자동 변경하지 않는다.
