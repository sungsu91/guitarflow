## 현재 모바일 목록 (2026-09-15 후속 수정)

모바일은 데스크톱 파일 표와 별도 JSX로 표시한다. 상단 내 악보/에튀드 탭은 배경 없이 활성 밑줄만 사용하고, 추가 버튼과 검색/정렬은 같은 높이의 조밀한 직사각형이다. 전체/최근 연습/즐겨찾기는 폴더가 아닌 텍스트 필터다. 최근 연습은 실제 연습 시각이 있는 문서만 최신순으로 보여주고, 최근/즐겨찾기/검색은 모든 폴더를 대상으로 한다.

폴더는 아이콘·이름·개수·화살표 한 행, 악보는 제목·조건부 보조 정보·화살표 두 줄이다. 제목에 확장자를 덧붙이지 않고 표 머리글·수정일 칸·미리보기·상시 관리 메뉴를 모바일에서 제거했다. 편집 버튼으로 관리 모드를 열면 선택/폴더 이동/새 폴더와 행별 이름 변경·삭제·즐겨찾기를 사용할 수 있다. 원본 내보내기와 정보 수정은 기존 악보 연습 화면에 유지한다. 데스크톱 파일 표와 기존 관리 조작은 유지했다.

저장 키 `fretiva.score.folders.v1`은 유지하고 선택 속성 `favorites: {'pdf:ID': true, 'score:ID': true}`만 추가했다. 기존 v1 분류는 쓰기 없이 읽으며 favorites가 없으면 빈 객체로 취급한다. 즐겨찾기와 폴더 이동은 PDF Blob/음표 데이터를 수정하지 않는다. 기존 PDF 백업은 계속 사용 가능하지만 폴더/즐겨찾기 분류는 백업에 포함하지 않는다.

빈 위치는 폴더와 악보의 존재를 구분한다. 폴더만 있는 경우 악보 영역에만 ‘이 위치에 저장된 악보가 없습니다.’를 표시하고, 모두 비어 있을 때만 불러오기/만들기를 안내한다.

## 이전 구현 기록: 파일 탐색기 형태로 정리

후속 요청에 따라 보관함에 별도 `scoreFileBrowser.css`를 적용했다. 앱의 카드·그라데이션 버튼과 분리된 흰 파일 목록, 회색 열 머리글, 얇은 구분선, 문서 아이콘을 사용한다. 데스크톱은 이름·파일 형식·내용·수정한 날짜를 열로 표시하고, 모바일은 파일명 아래 보조 정보와 오른쪽 수정일로 표시한다. `ScoreFileIcon.jsx`는 SVG 문서 아이콘이다.

파일 확장자는 문서 유형을 알아보기 위한 표시이며 실제 제목이나 저장 ID를 변경하지 않는다. 경로 표시 ‘악보 보관함 › 내 악보’는 앱 내부 위치다. 운영체제 폴더를 새로 만들거나 기존 IndexedDB/localStorage 저장 방식을 변경하지 않았다.

이 변경 후 빌드와 `verify-score-library-layout.mjs`를 다시 실행했다. 390×844 및 1440×1000에서 제목 7개가 표시되고, 검색·정렬·이름 변경·삭제·재열기·재생·편집 전환이 통과했다. 두 화면 모두 페이지/콘솔 오류가 없었다. 실제 휴대폰 검증은 별도다.

- 상단 메인 탭은 `내 악보 / 에튀드`. 목록과 연습 화면에서 유지하며 스크롤 시 상단에 고정한다. 앱 루트의 overflow 때문에 CSS sticky만으로 고정되지 않아 이 탭에만 위치 보정을 적용했다.
- 내 악보 목록에서만 작은 `+ PDF 불러오기 / + 간단 악보 만들기` 버튼을 제공한다. PDF와 편집 문서를 하나의 검색·정렬 목록으로 표시한다.
- 목록은 제목 + 문서 유형/페이지 또는 마디 수/BPM/기존에 있는 최근 위치의 두 줄. 큰 썸네일은 렌더링하지 않는다. 저장된 PDF 썸네일과 원본 파일은 그대로 보존한다.
- 항목을 누르면 PDF 연습 화면 또는 편집 문서의 보기·재생 화면을 연다. 오른쪽 ⋮에는 이름 변경과 삭제만 둔다. 삭제 확인, 실패 안내를 유지한다.
- PDF 정보 수정·원본 내보내기는 열린 PDF의 연습 설정에 있고, 간단 편집도 기존 PDF 화면에서 실행한다. 편집 문서는 열린 보기 화면의 ‘악보 편집’으로 기존 편집기를 사용한다. 파일 불러오기는 간단 악보 만들기의 파일 메뉴로 모았다. 목록 아래의 중복 불러오기는 제거했다.
- 에튀드 탭은 유형·곡 드롭다운과 유형 내 이전/다음 쪽넘김으로 바로 기존 연습 화면을 연다. 기존 곡 데이터, TIP, 재생, 편집 기능을 유지한다.
- PDF의 미저장 메모/저장 실패가 있으면 탭 이동에도 기존 닫기 확인 절차를 적용한다.

## 저장과 재사용

PDF는 기존 IndexedDB, 편집 문서는 `fretiva.etude.library.v2`를 그대로 사용한다. 새 보관함이나 중복 악보 데이터는 만들지 않았다. 편집 악보의 이름 변경은 title만 바꾸며 마디·음표를 컴파일하거나 재생성하지 않는다. 삭제는 해당 ID의 레코드만 제거한다. 저장 후에도 기존 생성/연습 시각 메타데이터를 보존한다.

`EditablePractice`는 기존 `compileScoreDocument`, `Score`, `ScorePlayback`을 조합한 읽기·재생 화면이며 새 편집기가 아니다. 기존 `ScoreEditor`와 PDF 간단 편집, 저장 큐, 닫기 가드를 재사용한다.

## 콘솔 오류 확인

작업 시작 시 현재 Vite의 `/src/etudes/ScorePlayback.jsx`는 HTTP 200이었다. `EditorScore`, `PdfPage`, `PdfContinuous`에서 `useScorePinch`는 모두 조건 없이 호출되며, enabled 분기는 훅 내부 effect에 있다. 현재 파일을 새로 열고 모바일/데스크톱 전환, 단일/연속 PDF, 편집기 열기/닫기 및 핀치를 검사했을 때 Hooks 순서 오류나 해당 모듈 404는 재현되지 않았다. 재현되지 않은 오류를 새 코드 수정으로 해결했다고 취급하지 않는다.

## 불러오기와 에튀드 범위 분리

내 악보의 간단 만들기는 `파일 → 불러오기…` 한 곳에서 FRETIVA JSON과 PDF를 선택한다. JSON은 기존 편집 데이터로 가져오고 PDF는 기존 닫기/미저장 확인을 거쳐 PDF 원본 보기로 연다. OMR은 개발용 제한 프로토타입이며 이 메뉴에서 자동 변환하지 않는다. `compactImport`는 PdfStudio의 편집기에만 전달한다. EtudeStudio는 기존 파일 메뉴를 유지한다. 파일 탐색기 CSS는 `data-library-view="pdf"`에 한정했다.

## 사용자 폴더 / 제공 에튀드 분리 (추가)

- 내 악보: 새 폴더 → 선택 편집 → 여러 파일 선택 → 폴더로 이동. PDF와 편집 악보를 함께 이동한다. 폴더 이름 변경과 삭제를 지원하며 삭제는 안의 악보를 기본 위치로 돌려놓는다. 검색은 모든 폴더의 악보를 찾는다.
- 폴더 정보만 `fretiva.score.folders.v1`에 `{version,folders,locations}`로 저장한다. `locations`의 키는 `pdf:ID` 또는 `score:ID`. PDF Blob/편집 문서는 기존 저장소 그대로이며 이동할 때 음악 데이터를 쓰지 않는다. 기존 악보는 연결 정보가 없으면 기본 위치에 표시한다. 저장 성공 후에만 UI를 갱신하고 실패 시 입력을 유지한다. 다른 탭의 storage 이벤트를 반영한다.
- 이 폴더는 앱의 기기 로컬 분류이며 운영체제 폴더가 아니다. 기존 PDF 백업은 PDF 원본과 편집 설정을 보관하며 이번 폴더 분류는 포함하지 않는다. 중첩 폴더는 이번 범위에 없다.
- 에튀드: 파일/폴더 화면을 사용하지 않는다. 기존 87곡은 9개 유형 드롭다운으로 선택하고 해당 유형의 총 곡 수를 기준으로 쪽넘김한다. 기존 제목/악보/난이도/연습 도구는 보존한다.
- 검증: 모바일390×844·데스크톱1440×1000에서 PDF와 JSON 동시 이동, 저장 후 재로드, 폴더 이름 변경/삭제, 악보 열기 후 폴더 복귀, 원본 PDF 해시와 JSON 보존, 9개 에튀드 유형별 목록과 이전/다음 경계 확인. 브라우저 오류 없음. 폴더 단위 테스트4개(저장 오류·잘못된 데이터 포함) 통과. 실제 휴대폰 하드웨어 검증은 별도.
