# 악보 입력·표기 점검

## 수정한 문제

- 프렛 교체, 같은 위치의 다른 줄 추가, X/쉼표 입력은 이미 지정된 길이(점8분·3연음 포함)를 유지한다. 입력 길이 버튼을 명시적으로 선택했을 때만 기존 음의 길이가 바뀐다.
- 길이를 늘릴 때는 연속된 빈 시간만 사용한다. 일부만 사용하는 빈 위치는 남은 길이로 나눈다. 뒤쪽의 입력 음표·명시적 쉼표를 덮거나 마디 끝을 넘어가는 변경은 적용하지 않는다.
- 점8분을 먼저 준비하고 숫자·X·쉼표를 입력해도 점이 사라지지 않는다. 일반 8분음표 버튼을 누르면 점을 해제하고 남은 시간을 비워 둔다.
- TAB 빔은 오선보의 실제 빔 계산 결과를 공유한다. 혼합 길이에서 고립된 16분음표의 짧은 보조 빔도 방향과 연결이 일치한다.
- 음을 삭제하거나 쉼표로 바꾼 뒤에도 범위의 빔 자동 복원이 가능하다. 3연음 일부의 빔을 끊는 것은 시간이나 묶음 정보를 바꾸지 않는다. 개별 연결에서도 서로 다른 3연음 묶음을 우회해 연결하지 않는다.
- 이전 두 자리 입력 모드와 빈 슬롯 처리 방식에 맞춰져 있던 오래된 검사 기대값을 현재 입력 동작에 맞게 갱신했다.

## 검증

- 관련 단위 테스트 83개 통과: 입력, 길이, 빔, 점음표, 3연음, 빈 슬롯, 뮤트, 주법, 재생 시간, 저장.
- `scripts/verify-mixed-beams.mjs`: 390px/1440px에서 혼합 빔·16분 3개·점8분+16분 3개, 저장·불러오기, Undo/Redo, 시간 불변 확인.
- `scripts/verify-score-audit.mjs`: 모바일/데스크톱 입력 회귀 검사. 각각 144개 렌더링 조합(보기·리듬 표시·자동/수동·6가지 혼합 패턴), 예외 및 NaN 좌표 없음.
- `scripts/verify-playback-cursor.mjs`: 실제 브라우저 재생 시 8분음표/3연음의 진행선, AudioContext 시간, 줄 이동, 정지 후 정리 검사.
- 프로덕션 빌드 통과. 기존 번들 크기 경고는 남아 있다.

## 지원 범위

이번 점검은 현재 편집기에서 제공되는 기능의 입력·표시·재생 일치와 데이터 보존을 대상으로 했다. 32·64분음표, 점8분 이외의 점음표, 마디를 가로지르는 H/P/슬라이드는 여전히 미지원이다. 이것은 음악적으로 불가능하다는 의미가 아니라 현재 편집기의 기능 범위다. 실제 iPhone 기기 검사는 하지 않았다.
